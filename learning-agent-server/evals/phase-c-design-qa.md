## 主流程验证

| 场景 | 结果 | 证据 |
| --- | --- | --- |
| 首次进入只有一个对话主界面 | 通过 | 大纲、讲义、分隔条在建档前隐藏 |
| 选择题位于输入框正上方 | 通过 | DOM 顺序为 `choiceTray` 后接 `chatForm` |
| 通常 3–4 个选项，最多不超过 10 | 通过 | 首题 4 个选项，前端统一截断为 10 |
| 零基础点击后立即开课 | 通过 | 4 次点击完成主题、目标、基础、时长；不调用诊断接口 |
| 学过一点或熟练者自适应诊断 | 通过 | 真实回归为 3–4 题，服务端硬上限 10 |
| 左大纲 / 中讲义 / 右对话 | 通过 | 与目标稿保持相同信息架构 |
| 中央和对话宽度可调 | 通过 | 鼠标拖动与方向键均可调整，本次键盘验证 390px → 414px |
| Markdown 和代码高亮 | 通过 | Markdown 先转义 HTML；Go 代码页识别到 3 个关键字高亮节点 |
| 翻页与课程进度 | 通过 | 5 页结构化课程、页码、上一页/下一页和进度信息正常 |
| 随堂选择题 | 通过 | 第 3 页渲染 3 个真实按钮，正确答案不下发浏览器 |
| 练习目录 | 通过 | 第 4 页显示 `projects/go-first-steps/lesson-01`，对应文件已创建 |
| 正确反馈 | 通过 | 正确后出现彩片动画和右上角“你真棒”提示，并自动进入练习页 |
| Anki 三档复习 | 通过 | 红色“没想起来”、黄色“稍微有点困难”、绿色“顺利”位于输入框上方 |
| 移动端 | 通过 | 390 × 844 下对话、4 个选项和输入框均完整可见 |

## 视觉结论

实现与目标稿保持了暖白纸张、深墨文字、陶土强调色、细边框、低圆角和三栏学习剧场。首次进入比目标稿更克制，只显示对话；课程开始后再恢复三栏。第一页刻意保持较多留白，一页只推进一个概念；代码、题目和练习拆到后续页面，避免把零基础用户一次淹没。
