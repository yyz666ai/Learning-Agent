# Phase B 教学链路评测报告

## 结论

Phase B 已把首次开课从最多 3 轮缩短到 1–2 步，并把熟练者摸底改为 3–4 道真实点击题。2026-08-20 的最终真实链路回归中，四类画像全部通过教学质量门槛；每轮只留下一个当前问题，不再重复询问已由界面确认的基础信息。

## 教学质量评价

- 生动性：四个场景都包含具体比喻或场景，例如外卖通知、后厨传话、请求流和第一个可运行程序。
- 小步性：选择题与动手题不再同轮出现；每轮最多一个新核心概念和一个可见当前问题。
- 诊断效率：零基础不诊断；有基础者通常 3 道稳定答案完成，边界状态补第 4 道，硬上限仍为 10 道。
- 状态可靠性：四个用户均生成可解析的 `learning-state.json` 和可读取的 `plans/*.md`，画像确认后不再回到聊天式摸底。
- 练习闭环：每个模块可以生成新题，提交后返回结构化评价；只有 `correct=true` 且 `verified=true` 才触发庆祝，并把记录写入复习讲义。

## 仍需诚实说明的限制

1. FastAPI 已通过 SSE 流式发送连接状态和正文事件，但当前 Codex CLI 常在模型完成后才给出一整段正文，所以还不是稳定的逐 token 打字效果。若要做到真正逐 token，需要 harness 暴露模型增量，或直接接入 DeepSeek 的流式响应。
2. HTML 课件仍由模型生成。Skill 已增加“题干、讲解与正确选项逐项自检”规则，但客户端自行判题仍有语义漂移风险。上线前建议改为结构化课件 JSON + 服务端验证题库，再由前端负责渲染。
3. 18–38 秒的真实链路耗时适合作为当前功能验证，不是理想交互指标；下一阶段应增加预生成首课、缓存和可取消请求。
