先看场景

客服机器人答不上新政策

今年公司出了一份新休假政策，比如「今年起每年多两天年假」。老板让客服机器人回答客户的问题，可是你问它： “今年新出的休假政策是什么？” 它支支吾吾答不上来，或者干脆编一个。 为什么？因为它是在「过去」被训练的，只记得训练时见过的资料；这份政策是训练之后才有的，它根本没见过。 就像一位很聪明的老员工，他入职那年还没有这份政策，你问他，他只能靠猜。 **本页请做**：先别翻页，在心里猜一下：模型答不上来，是因为它“笨”，还是因为“没见过这份资料”？记住你的答案。

两种笨办法

硬答 vs 重训，都不划算

要让模型回答新政策，有两个「笨办法」： | 做法 | 结果 | | --- | --- | | 凭记忆硬答 | 不知道，就瞎编一个 | | 重新训练模型 | 慢、贵，政策变了还得再来一遍 | 硬答会骗人，重训又太慢。所以换个思路：**先查资料，再作答**——回答前，先把资料库里相关的那段找出来，让模型照着答。 就像考试：闭卷靠背，会忘、会编；**开卷翻书**才稳。 **本页请做**：在心里用两个词记住这两种笨办法（比如“瞎编”和“重训”），然后点下一页，看看“开卷”怎么做。

RAG 的思路

先查资料，再作答（开卷考试）

RAG（检索增强生成）就是给模型“开卷考试”：回答前，先到资料库（比如公司文档）里检索相关段落，把段落拼进问题，再让模型照着作答。 ```mermaid flowchart LR A[用户问：今年新出的休假政策？] --> B[① 去资料库检索] B --> C[② 找到新政策那一段] C --> D[③ 把段落拼进问题] D --> E[④ 模型照着资料回答] ``` 适合 RAG 的场景：资料经常变（比如新政策）、只有内部文档才知道的内容。 边界：资料库里没有的，RAG 也答不上——它只负责“查得到、答得准”。 **本页请做**：看图把流程默背一遍：提问 → 查资料 → 拼进去 → 作答；然后点下一页做判断。
