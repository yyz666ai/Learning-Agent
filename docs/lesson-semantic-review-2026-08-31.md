# 课件知识点覆盖：从词面门禁改为模型语义审阅

## 已修改的根因

此前代码将知识点标题拆成词组，要求模型引用的至少两页出现指定词组。它无法可靠区分同义表达和真正漏讲。内容已经写出，却可能被标为结构错误；同样的检查还会驱动一次整份修复调用。

现在删除该词面检查及标题拆词逻辑。生成提示不再要求原词或固定两页，后台也不依赖生成者自报的 `scope_evidence`。历史课件里的该字段不影响新审阅。原技术标题/Go/教学编排相关测试已迁移为完整原始标题与正文的传递、模型判断的执行和审阅协议验证，而不是继续测试错误的字面匹配政策。

## 当前流程

1. 按当前章的知识点、目标、基础和练习要求生成课件。
2. 代码校验页面数据、唯一 ID、题目与答案、路径等现有结构约束。允许现有的确定性格式修复；真正结构错误仍最多请求一次结构修复。
3. 独立调用项目配置的模型，进行一次整章语义审阅。提供完整原始知识点及 outcome/practice/mastery_criteria、学习者基础、正文、代码、题目、面试卡片。生成与审阅使用相同的本章目标。
4. 对每个知识点返回 `covered`、`missing` 或 `uncertain`，附中文理由和证据页面。代码只验证报告格式、知识点集合、引用页面真实性，不匹配教学关键词。
5. 全部 covered 才保存新课件；原有的项目切换保护在真正保存前继续执行。

语义覆盖允许同义词、中英文别名、代码演示、一页讲清楚及多个知识点共用页面。不接受只写标题、堆关键词或推迟到以后再讲。是否实质讲到由模型判断，不以这些词语是否出现为条件。

审阅通过专用 `lesson_review` 调用类型，沿用项目 Codex/DeepSeek 配置，不更改全局配置。该调用不重新装载生成用的一组 Skills，不读取旧课程画像，不上网或执行工具。后台会打印独立的开始、结束、耗时和判定数量。

## 错误与保存边界

| 状况 | 接口 error_type | 行为 |
| --- | --- | --- |
| 真正页面/答案结构错误 | validation | 保留现有结构修复逻辑 |
| 模型明确判断漏讲 | content_review | 告知具体知识点及理由，不替换原课件 |
| 审阅超时、输出无效、无法判断 | review_unavailable | 提示审阅未完成，不冒充结构错误，不宣称通过 |

后两者的 error_stage 为 `lesson_review`。Bug 导出只记录脱敏分类和规则代号，不导出理由原文、用户资料或 API Key。

语义审阅位于结构修复循环之后，审阅不通过不会自动重写课件。当前用户手动点击“重新生成”仍是一次新生成任务，并非只续跑审阅；本次未增加候选课件的断点续审缓存。

本次没有修改 Plan 生成、右侧自然语言编辑范围或页面选择逻辑，不能把这次修复当作那些独立问题已完成。已有课件的读取也不强制增加审阅费用；新生成走新审阅流程。

在隔离目录使用项目 DeepSeek 配置，原用户文件只读，不写入其课件、Plan 或练习：

| 测试 | 结果 | 单次耗时 |
| --- | --- | --- |
| 原先失败的 13 页 Vue 入门课件，5 个知识点 | 审阅全部 covered，未改写原文 | 三次分别 5.24、3.78、10.69 秒 |

完整新生成样本：内容生成 39.42 秒 + 独立审阅 4.22 秒；两次模型调用，均 0 工具调用、0 流恢复错误、无思考输出。耗时是本次单样本，不是上限或服务承诺。大模型仍可能误判，不能保证所有未来课程都零错误。

测试初建隔离目录时漏带模型配置模板，产生过无效超时样本；补齐项目模板后才得到上述真实 DeepSeek 结果。无效样本不计入质量和耗时统计。

可复现入口：`tools/evaluate_semantic_review.py --rollout <原生成记录.jsonl> --curriculum <curriculum.json> --generate`。该脚本会发生 API 费用，运行输出留在被忽略的 `evals/runs/`；不随 Git 提交。

回归覆盖：同义表达、单页覆盖、逐项报告完整性、虚构引用、重复判断、漏讲、无法判断、超时、失败不自动重写、旧课件不被覆盖、专用无工具调用和接口错误分类。自动化测试中的模型返回是显式测试替身，语义判断能力由上面的真实模型正反例另行验证。
