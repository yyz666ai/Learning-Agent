# 诊断题失败排查与验证（2026-08-30）

## 结论

本次截图停在诊断题生成，尚未开始 Plan。失败记录耗时 **2.07 秒**，并非长请求超时。

本机同时存在手动启动的后端与 `com.learning-agent.local` 自动启动服务。后者因 8787 已被占用而退出，又被自动拉起；排查时已累计启动 659 次。原启动顺序是部署检查 → 发布 → 绑定端口，因此每一次失败启动都会先删除并重建 `workspace/releases/current`。

Codex 正以该目录为工作目录。路径虽然重新出现，但进程仍持有已删除目录，真实复现出现：

```text
fatal: Unable to read current working directory: No such file or directory
Error: thread/start: thread/start failed: failed to load configuration:
No such file or directory (os error 2)
```

另一个输入缺口：诊断原来只接收主题、水平、路线，未接收本轮已经确认的 Vue 技术栈。此前 Plan/课件性能实测从确认后的画像开始，没有覆盖自然建档后的诊断入口。

## 修复范围

1. 启动前检查端口；已有服务时不再执行发布。兼容正常重启后的 TIME_WAIT，Windows 使用独占绑定检查。
2. 发布保留 current 目录本身，先暂存全部待发布文件，再逐文件原子替换；最后更新发布清单。只移除旧清单中不再发布的文件，不清理用户数据。复制失败不会先删掉旧版本。
3. 诊断接入已有的受限 Codex 生成通道：一次提供完整 adaptive-onboarding Skill，禁用工具、关闭思考、要求 JSON，仍保留结构校验和一次格式修复，不以通用题冒充岗位题。
4. 当前确认的岗位、技术栈、基础证据传入诊断；不读取可能属于上一门课程的 profile.md。增加版本差异必须在题干注明的要求，避免混用旧版 API。
5. 诊断失败、取消、中断后，前端显示“诊断已停止”，不再同时声称“正在校准起点”。
6. 停止本次手动运行的旧服务，由既有自动启动服务单独接管 8787；未删除学习目标、回答或项目。

发布现在是逐文件更新，并不是整套文件的事务快照；大幅升级仍应在没有生成任务时进行。外部 API、网络和模型内容质量仍可能失败，不承诺任何情况下永不失败。
