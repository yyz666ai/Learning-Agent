# Plan 与课件生成事务隔离设计

## 问题

当前 Plan 与课件生成是长时间同步请求。前端五分钟后会放弃请求并恢复旧项目，但后端 Codex 进程仍会继续，完成后直接覆盖用户活动目录。与此同时，中文主题会被移除为相同的英文 slug，例如 `AI` 与 `AI前端` 都落到 `ai-plan.md`。这会让学习状态、Plan、课程树和课件分别属于不同项目。

## 目标

- 每次生成都绑定唯一 `generation_id`、目标主题、目标 Plan 路径和项目修订号。
- 模型输出先进入任务暂存区，绝不直接写活动项目。
- 提交前再次确认任务仍是当前任务；超时、取消、恢复或切换后，旧结果必须被拒绝。
- Plan、课程树和学习状态作为一个事务提交；任一步失败都恢复原文件。
- 课件生成也校验主题、课程树和当前知识点，不能向错误项目写入。
- 中文或相似主题使用“可读 slug + 短哈希”，不再共用文件。

## 方案

### 1. 生成租约

`onboarding/confirm` 创建 `generation_id`，并把它与 `topic_key`、`active_plan`、`project_revision` 写入 `learning-state.json`。前端随后把该 ID 传给 Plan 生成接口。

恢复、切换、删除或重新开始项目时，活动状态发生变化，旧租约自然失效。前端超时还会显式调用取消接口，把该任务标为 cancelled。

### 2. 暂存和事务提交

模型生成和校验阶段只在内存及 `.generation-jobs/<generation_id>/` 中工作。最终提交时在用户级锁内重新读取状态，严格比较 generation ID、主题、Plan 路径和修订号。只有全部一致才替换 Plan、`curriculum.json` 和 `learning-state.json`。

提交会为旧文件建立临时备份；任意替换失败时执行回滚。若回滚本身失败，保留恢复目录并返回明确错误，不删除唯一备份。

### 3. 安全文件名

Plan 文件名由 Unicode 主题的可读转写片段和 SHA-256 短哈希组成。`AI`、`AI前端`、纯中文主题都会得到不同路径。旧项目继续读取原路径，不强制迁移；新项目使用新规则。

### 4. 前端行为

前端不再在固定五分钟后直接恢复项目。它展示阶段进度，并以比后端更长的兜底时间等待。若用户主动返回、切换项目或请求超时，先取消 generation ID，再恢复快照。取消失败不影响恢复，但后端提交门仍会拒绝旧租约。

### 5. 课件门禁

课件请求携带当前 project revision。后端在生成前和落盘前分别检查：Plan 已确认、topic/route 与 curriculum 一致、知识点仍是当前知识点、项目 revision 未变化。失败返回 `stale_generation`，前端重新加载当前课程，而不是显示笼统的 Failed to fetch。

## 数据修复

对当前 `u_yang` 先做完整恢复备份，再根据用户正在学习的有效项目恢复一致的 Plan、curriculum 和 state。无法可靠判断归属的混合文件不删除，移动到带时间戳的恢复目录。

## 验收

- `AI` 与 `AI前端` 的 Plan 路径不同。
- Plan 生成过程中恢复旧项目，迟到结果不能修改旧项目任何文件。
- Plan 生成过程中开始另一主题，第一轮结果不能覆盖第二轮。
- 事务提交中途失败，三份文件保持原样。
- 刷新、重复点击和前端超时不会产生跨项目混合状态。
- Plan 确认后才能生成课件；课件落盘前项目已切换时必须放弃写入。
