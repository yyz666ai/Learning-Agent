# Learning Agent 对话驱动学习剧场设计

**状态：** 已确认，待实施

**日期：** 2026-08-20

**视觉目标：** `docs/superpowers/specs/assets/chat-first-learning-theater.png`

**范围：** 对话式首次分流、可拖动学习剧场、动态 HTML PPT、真实文件练习、Anki 式复习、学习提醒、学习档案、计划策略与相关 Skills

**暂不包含：** GitHub 推送、多人协作、公共知识库 PR 工作流、云端部署

**扩展设计：** `2026-08-20-interview-question-bank-design.md` 定义持续采集面试题、题库扩展、左栏掌握状态和不回退进度的增量计划。

**2026-08-22 意图识别更新：** 首屏不再展示“继续上次”选择题，学习项目与历史改为常驻左栏直接打开；新学习从唯一文本框自由输入开始，由 Codex 读取 `learning-intent-router` Skill 进行多轮 slot filling。详见 `2026-08-22-agentic-intent-onboarding-design.md`。

## 1. 产品原则

Learning Agent 只有一个交互中心：**对话**。

- 首次打开时，除窄版学习项目栏外，只显示 Codex 式对话。
- 学习目标、当前水平、每日时长和路线偏好都通过对话下方的点击选项采集；不出现独立的大表单页面。
- 开课后，对话触发左侧 HTML PPT/Markdown 学习内容；PPT 不是第二套导航。
- 课程大纲只显示位置、进度、复习和历史项目，不承担当前任务的复杂操作。
- 每一项掌握结论必须来自选择判断、回忆表现、真实文件、运行输出、测试结果或独立解释；仅浏览页面不算掌握。

## 2. 核心页面与状态

### 2.1 首次打开：对话优先

页面由窄版项目栏和主对话区组成。主对话依次询问：

1. 今天想学什么。
2. 想达到什么结果。
3. 当前基础。
4. 每天能投入多长时间，以及是否有截止日期。

每个问题的候选项直接出现在 assistant 消息下方，是可点击按钮，不要求用户把选项重新输入聊天框。允许用户直接输入自定义主题或项目路径。

选择题使用固定在消息流底部、输入框正上方的 **inline choice tray**：它是对话的一部分，不是模态框、居中弹窗、独立页面或覆盖层。托盘始终贴近输入框，显示当前问题、轻量进度和 2–5 个纵向或横向选项；用户点击后托盘原地锁定答案并自然进入下一问。选项数量通常为 3–4 个，只在题意确实需要时扩展到 5 个。

零基础且目标明确时，1–2 步后直接开课。学过一点或熟练者可追加 3–4 道点击诊断；边界不清时继续追加，但不得超过 10 道。

诊断必须逐题自适应：每答完一题，后端重新判断是否已经足够确定。默认 3–4 题；如果答案稳定立即结束，如果答案矛盾才一次追加一题，任何情况下不得预先生成或一次展示超过 10 题。诊断完成后 inline choice tray 退出诊断状态，但继续用于课程中的选择检测和 Anki 快问快答。

### 2.2 开课：学习剧场

开课后形成三部分：

- **左栏：** 当前学习项目、大纲、预计剩余时间、今日回顾、学习档案。
- **中间：** HTML PPT、Markdown 讲义、代码、练习路径和翻页控制。
- **右栏：** 持续的 Codex 式对话、点击题、简答、提示、评价和下一步。

中间与右栏之间使用可拖动分隔条。用户可把讲义扩大到约 75%，也可把对话扩大到约 60%；比例按用户和设备持久化。PPT 尚未打开时，对话自动占据主区域，不保留空白画布。

移动端不并排显示三栏：默认显示对话，讲义和大纲以独立全屏层打开，并保留当前位置。

### 2.3 学习与复习是两套 PPT

- **学习 PPT：** 建立新概念、示例、检测、真实练习和掌握反馈。
- **复习 PPT：** 快速回忆、错题补救、知识关系、实战检验和复习结论。

两者使用同一渲染器和概念 ID，但页面编排、题目密度和完成标准不同。

## 3. 计划驱动的教学策略

系统不为每一类用户复制整套 Skill。`plan.md` 由三个维度共同决定：

1. **目标路线：** 用户最终想做到什么。
2. **能力覆盖：** 零基础、初学、中级、工程师或高级工程师。
3. **约束：** 每日时长、截止日期、项目路径和最终产物。

### 3.1 七类目标路线

| 路线 ID | 用户结果 | 讲解与题型策略 | 毕业证据 |
| --- | --- | --- | --- |
| `foundation_engineer` | 从零成长为能独立做项目的工程师 | 完整学习、复习、选择题、简答、真实作业、阶段考试 | 独立完成并解释一个综合项目 |
| `urgent_codebase` | 在短期限内看懂指定项目 | 减少间隔记忆，增加语法扫盲、调用链、文件职责和代码判断 | 能解释入口、调用链并修改一个目标位置 |
| `syntax_reading` | 能读懂某语言或项目语法 | 讲义、代码阅读、输出预测、选择判断为主 | 能逐段解释目标代码 |
| `project_delivery` | 真正交付某个功能 | 简短讲解，大量脚手架、运行、调试和测试 | 真实文件和测试通过 |
| `gap_upgrade` | 中级学习者补齐薄弱环节 | 已掌握内容快进；薄弱点恢复小白式教学 | 弱项通过迁移题 |
| `senior_engineer` | 工程师进阶高级工程师 | 大型项目、架构取舍、可靠性、性能、重构和评审 | 完成设计文档、实现、测试与复盘 |
| `interview_sprint` | 面试或专项冲刺 | 少量选择题，大量简答、追问、代码推演和限时表达 | 按知识库 rubric 完成模拟面试 |

能力水平是上述路线的速度覆盖层：连续稳定答对则快进；出现先修缺口则插入最小补救单元；不得因为用户自称熟练就跳过证据验证。

### 3.2 `plan.md` 必须包含

- 目标路线、主题、当前能力和诊断证据。
- 截止日期、每日时长、预计总时长和每阶段时长。
- 阶段、概念依赖、项目里程碑和当前任务。
- 讲义密度、允许快进规则、题型配比和真实练习配比。
- Anki 强度、每日复习预算和错题补救规则。
- 练习目录、最终产物和毕业证据。
- 提醒时间、提醒类型和时区。
- 策略版本，便于后续重新规划和追踪差异。

后端校验计划 Schema 和文件路径。模型负责做教学判断，但不得自由决定状态是否写入或声称作业已经完成。

## 4. 动态 PPT 编排

### 4.1 页数和题数不固定

模型按以下输入生成本节 `lesson-manifest.json`：

- 概念密度和难度。
- 前置知识缺口。
- 用户最近的错误、回答速度和提示次数。
- 目标路线与截止日期。
- 当日剩余学习时间。
- 是否需要真实编程证据。

页面类型包括：

- `explain`：生活化直觉和概念。
- `example`：Markdown 代码与逐行解释。
- `check`：一到多道点击题或简答题。
- `practice`：真实文件任务。
- `summary`：本节关键关系与误区。
- `mastery`：证据结论、庆祝和下一步。

高密度页面允许出现多道相关快速题；低密度内容可以连续讲解后再检测。编排器应保持一个页面只服务一个概念簇，不把互不相关的问题塞进同一页。

### 4.2 进度计算

PPT 顶部同时显示：

- 当前页 / 总页数。
- 本节掌握度。
- 预计剩余时间。

页数进度只表示浏览位置；掌握度来自问题、练习和运行证据。未完成检测门时可以回看前页，但不能把概念标记为已掌握。

### 4.3 结构化内容安全

模型不再直接生成带任意判题 JavaScript 的整块 HTML。它输出经过 Schema 约束的页面、Markdown、代码、题目引用和转场信息；前端使用统一渲染器生成 PPT。正确答案、rubric 和状态更新保留在后端。

所有 Markdown 必须支持标题、列表、引用、表格、行内代码和 fenced code block。代码块提供语言识别、语法高亮、复制和横向滚动。渲染必须经过 HTML 清理，不执行模型输出的脚本。

## 5. 真实文件练习

每个动手任务在用户目录下生成隔离工作区：

```text
userdir/u_<user>/projects/<plan-id>/<lesson-id>/
├── README.md
├── task.md
├── starter files
└── tests/
```

PPT 底部固定展示工作区相对路径、复制路径、查看任务和运行命令。Agent 可以生成脚手架、测试和说明，但不得替用户补完被评价的核心代码。

提交时收集：

- 文件内容或安全 diff。
- 运行命令与退出状态。
- 标准输出、标准错误和测试结果。
- 用户的解释或设计理由。

客观测试优先零 token 判定；开放式设计、面试表达和工程取舍再调用模型，并要求模型按知识库 rubric 返回结构化评价。

## 6. Anki 式复习引擎

### 6.1 三档自评

显示答案或完成回忆后，只提供三个按钮：

- **没想起来（红色）：** 记为遗忘，缩短间隔，安排即时补救并在当天再次出现。
- **稍微有点困难（黄色）：** 回答基本正确但回忆慢，适度缩短间隔，并补一道相邻变式题。
- **顺利（绿色）：** 快速、完整且证据一致，延长复习间隔。

客观题由后端判断正误，自评负责描述回忆难度；两者都进入排程。用户把错误答案标为“顺利”时，客观结果优先，不能延长间隔。

### 6.2 卡片记录

每张卡片至少保存：

- `concept_id`、题干、题型、答案或 rubric 版本。
- 难度、稳定度、到期时间、遗忘次数和最近表现。
- 关联讲义页、错误类型和证据引用。
- 来源知识库版本，便于题目更新后重新校准。

### 6.3 每日复习流程

1. **基础测试：** 从到期卡片读取快问快答，优先使用固定题和本地 checker，不调用模型。
2. **错题补救：** 答错后打开对应复习 PPT；仍不能解释时才调用模型生成针对性讲解。
3. **实战检验：** 普通学习者最后完成一到两道编程题；高级学习者直接从工程任务开始，失败后再回溯知识卡。

题量由每日时间预算决定，而不是固定数量：

| 每日复习时间 | 建议内容 |
| ---: | --- |
| 10 分钟 | 到期快问快答 + 1 道微型应用题 |
| 25 分钟 | 到期卡片 + 错题补救 + 1 道动手题 |
| 45 分钟 | 完整回顾 + 补救讲义 + 2 道实战题 |

系统以估算答题时间填满预算，优先级依次为逾期卡、易错点、当前项目依赖和长期未复习概念。

## 7. 面试冲刺模式

面试知识库存储题目、追问树、评分 rubric、优秀答案结构和常见误区。流程以实战表达为主：

1. 对话中弹出简答题或代码推演题。
2. 用户口述转文字或直接输入答案。
3. 模型按 rubric 评价完整性、准确性、结构和表达。
4. 根据遗漏项继续追问，而不是立刻给参考答案。
5. 易错点写成 Anki 卡片，并进入后续模拟面试。

选择题只用于快速定位，不作为主要训练形式。

## 8. 庆祝与反馈

只有后端返回 `correct=true` 且 `verified=true`，或真实测试满足完成标准时，才触发庆祝。

- 小题正确：按钮状态变化和一句短反馈。
- 掌握一个概念：右上角弹出“你真棒”“这次是独立完成的”“你已经掌握了变量声明”等上下文相关文案。
- 完成作业、阶段或项目：播放 1–2 秒的彩片爆竹庆祝动画，同时推进大纲进度。
- 查看答案、跳过、证据不足或评分失败时不庆祝。
- 支持 `prefers-reduced-motion` 和用户关闭动画；关闭后只显示静态成功提示。

网页运行时使用本地打包的动效实现，不依赖远程 CDN，不阻塞翻页、输入或继续学习。

## 9. 左栏与学习档案

左栏只有三层：

1. **当前学习：** 课程、章节、作业、总进度和预计完成时间。
2. **今日回顾：** 到期卡片数量、预计耗时和进入复习。
3. **学习档案：** 历史计划、聊天、PPT、作业、评价与掌握记录。

手动“备份本次学习”或完成阶段时，生成不可变快照：

```text
archives/<plan-id>/<timestamp>/
├── plan.md
├── profile.md
├── progress.json
├── cards/
├── lessons/
├── attempts/
├── review-notes.md
└── archive-manifest.json
```

点击历史项目时先进入只读回顾；用户明确选择“继续这个项目”后，才从快照恢复为新的活动版本，避免误改历史记录。

## 10. 网页关闭后的提醒

用户在软件设置中配置学习时间、复习时间、时区、工作日和是否允许系统通知。侧栏通知按钮显示当前状态和下一次提醒时间。

本地版采用两级提醒：

1. 页面打开时使用浏览器通知和站内提示。
2. 页面关闭时由仍在运行的 Learning Agent 后端调度器调用操作系统通知适配器。

因此，网页可以关闭，但本地 Learning Agent 服务必须保持运行。macOS、Windows 和 Linux 使用独立适配器；测试环境只记录通知事件，不发送真实系统通知。未来云端多用户版再增加 Web Push 或外部消息渠道。

提醒文案基于真实状态，例如：“今天有 6 张卡片到期，预计 12 分钟”“Go 项目第 3 节还剩一个练习”。用户可以推迟、跳过今天或直接打开对应学习项目。

## 11. 组件与服务边界

- `ChatController`：唯一用户指令入口、流式消息和 inline actions。
- `ArtifactPane`：学习/复习 PPT、Markdown、代码和练习路径。
- `ResizableWorkspace`：桌面分栏、比例持久化与移动端层级切换。
- `CurriculumRail`：只读进度、今日复习和档案入口。
- `PlanStrategyService`：目标路线、能力覆盖、时间预算和计划 Schema。
- `LessonOrchestrator`：生成/读取 lesson manifest，管理检测门和页面进度。
- `PracticeWorkspaceService`：安全创建练习目录、运行允许的命令并收集证据。
- `ReviewScheduler`：卡片排程、三档自评和每日预算。
- `ReminderScheduler`：软件内设置、下一次提醒和操作系统通知。
- `ArchiveService`：快照、manifest、只读回顾和显式恢复。

这些模块通过结构化 API 和持久化文件通信，不让前端从模型自然语言推断状态。

## 12. 关键数据流

### 12.1 开课

对话选择目标 → 确定性诊断 → `PlanStrategyService` 写 `plan.md` → `LessonOrchestrator` 生成首节 manifest → 对话触发 ArtifactPane → 学习者逐页学习与答题。

### 12.2 动手作业

PPT 到达 practice 页 → 创建练习工作区 → 用户修改并运行 → 后端收集文件和测试证据 → 客观 checker / rubric 评分 → 写 attempt、卡片和进度 → verified 后庆祝。

### 12.3 每日复习

调度器计算到期卡片和时间预算 → 提醒 → 快问快答 → 三档自评 → 错题打开复习 PPT → 必要时模型讲解 → 实战题 → 更新卡片间隔和复习讲义。

## 13. 错误处理与安全

- 模型 manifest 不符合 Schema：拒绝保存，使用知识库模板或重新生成。
- Markdown 包含脚本或危险 HTML：清理后渲染，永不直接执行。
- 练习路径越界：拒绝创建或运行；所有路径必须落在当前用户的项目根目录。
- 命令不在允许列表或超时：终止运行并保留日志，不写掌握证据。
- 评分结构无法解析：标记为未验证，不庆祝、不延长复习间隔。
- 系统通知权限被拒绝：保留站内提醒，并在设置中展示修复方法。
- 后端未运行：不承诺网页关闭后的提醒；下次启动时显示错过的提醒。
- 档案写入中断：临时目录回滚，不产生半完成快照。

## 14. 测试与验收

### 14.1 自动测试

- Plan 七类路线、能力覆盖、时间预算和 Schema。
- 动态页数、多题页、检测门和掌握度不等于翻页进度。
- Markdown 安全清理、代码高亮、复制和长代码滚动。
- 分栏拖动、最小/最大宽度、比例持久化和移动端切换。
- 练习目录隔离、命令允许列表、超时、文件证据和测试评分。
- Anki 三档排程、客观错误覆盖自评、到期优先级和时间预算。
- 面试 rubric、追问树和易错卡片生成。
- verified 庆祝门、减少动态效果和静态反馈。
- 页面关闭提醒的调度、时区、跳过、推迟和权限失败。
- 档案快照完整性、只读打开和显式恢复。

### 14.2 浏览器验收

- 首次打开没有独立 onboarding 大表单。
- 点击消息下方选项即可完成画像并开课。
- 未打开 PPT 时对话占据主区域。
- 打开 PPT 后可拖动中间与对话宽度。
- 所有模型代码都以 Markdown 代码块高亮显示。
- 学习题、复习题和三档自评可只用鼠标或键盘完成。

## 18. 方案 B：课程树驱动的自适应教学闭环

### 18.1 本轮确认的根因

2026-08-20 的第二次真实浏览器审核确认，问题不是结束页提示文案不够醒目，而是课程引擎缺少状态转换：

2. 最后一页只发出 `page-change`，前端只显示文本提示；没有完成按钮、证据提交、模型评价或下一课加载接口。
3. `learning-state.json` 的 `active_task`、完成知识点和掌握证据没有被课程接口推进。
4. `＋` 新建学习项目直接清空当前界面进入画像流程，没有取消或返回入口，同时保留了上一课程的 step guide。

### 18.2 产品原则

- 大模型负责课程内容与教学判断，前端只负责可靠渲染和明确导航。
- 不在每次翻页时调用模型。进入一个知识点时由 Codex 一次生成本知识点完整 PPT；翻页即时完成，末页再调用 Codex 评价并决定下一步。
- 每个知识点必须至少经历一次模型生成；每次完成、补讲或进入下一知识点必须经过模型评价。
- 选择题答案仍可由后端客观判定，但题干、干扰项、解释、练习和完成标准来自当前学习者的课程生成结果。
- 模型失败时明确显示失败与重试，不再把无关语言或固定变量课静默当作个性化课程。

### 18.3 用户目录中的课程数据

每个学习项目保存以下文件：

- `curriculum.json`：结构化课程树，是章节、知识点、先修关系、预计时长和状态的唯一事实来源。
- `plan.md`：由 `curriculum.json` 渲染的详尽教材大纲，供用户阅读和共享。
- `lessons/<knowledge_point_id>.json`：Codex 为一个知识点生成并通过 Schema 验证的 PPT manifest。
- `learning-state.json`：保存当前知识点、完成列表、掌握度、最近证据和下一步动作。
- `attempts/`：保存末页提交、模型 rubric 评价和补讲原因。

课程树至少包含：

```text
chapter → knowledge_points → prerequisites / outcomes / practice / mastery_criteria
```

学习语言时，大纲必须拆到具体章节与知识点。例如 Go 需要覆盖环境与程序结构、变量与类型、控制流、函数、错误处理、集合与结构体、文件与测试、项目实战和迁移复习；Java、Rust 或其他语言由 Codex 按语言生态重新生成，不复用 Go 章节。

### 18.4 知识点 PPT 生成

`LessonOrchestrator` 读取当前画像、课程树当前知识点、已完成知识点、最近错题、上一课证据和单次时长，调用 Codex 生成 `LessonManifest`。

模型自行决定 3–12 页以及题目密度，允许一个高密度页面配置多道练习。Manifest 必须包含：

- 知识点目标与先修关系。
- 适合当前水平的解释、类比和代码。
- 选择题、短答或动手题。
- 真实练习目录及完成证据要求。
- 最后一页的 `completion_mode`、具体提交提示和三个结束动作。

模型结果不符合 Schema、语言或知识点不匹配时拒绝保存，并显示“课程生成失败，重新生成”；不能回退为无关固定课。

### 18.5 最后一页交互与课程状态机

最终页的 PPT 主区域内直接显示结束操作，不把主要动作藏在聊天输入框：

1. `提交本课成果`：按 `completion_mode` 展示点击题、短答框或运行结果框。
2. `我还没学会，再讲一次`：调用模型生成另一种类比和补讲 PPT。
3. `我卡在动手练习`：调用模型读取当前任务和错误描述，生成最小提示或分步排障。

提交证据后调用 `/api/lesson/complete`，Codex 返回结构化评价：

- `advance`：掌握达标，更新课程树状态并显示 `开始下一课：<具体知识点>`。
- `practice`：概念基本掌握但证据不足，生成一组针对性练习。
- `reteach`：存在关键误区，生成不同讲法的补讲 PPT。

下一课按钮必须位于 PPT 最后一页和右侧对话输入框上方；用户点击后才加载下一知识点。任何状态都不能只留下一个被禁用的“下一页”。

### 18.6 学习档案

- `当前计划` 打开项目档案视图，不触发重新画像。
- `＋ 新建学习项目` 使用明确文字按钮，进入新建流程后顶部始终显示 `← 返回当前课程`。
- 新项目只有在画像确认并成功写入新课程树后才切换；取消时完整恢复原课程、页码、聊天和 step guide。
- 进入新建流程时隐藏旧课程 step guide 和提示 chips，避免两个任务上下文混合。

### 18.7 API 与模块边界

- `POST /api/curriculum/generate`：生成并验证 `curriculum.json` 与 `plan.md`。
- `POST /api/lesson/generate`：为当前或指定知识点生成 PPT manifest。
- `GET /api/lesson/current`：只读取已保存 manifest；不存在时返回明确的 `lesson_generation_required`。
- `POST /api/lesson/complete`：评价证据、更新掌握状态并返回下一动作。
- `POST /api/lesson/remediate`：按 `reteach` 或 `practice` 生成补救 lesson。

新模块分别负责课程树 Schema、模型生成与校验、课程状态推进。`backend/main.py` 只做请求校验和错误映射，不能继续承载课程业务逻辑。

### 18.8 验收标准

- Java、Go 和 FastAPI 三种隔离用户生成完全不同且具体的章节树。
- 同一语言的零基础与熟练用户，其章节深度、首课内容、练习密度不同。
- 最后一页始终存在三个明确动作；提交评价后始终存在一个可点击下一状态。
- 完成第一知识点后重新请求课程，不能再次得到同一 manifest。
- 模型输出语言或知识点不匹配时拒绝保存，页面允许重试。
- 新建项目流程可以随时取消并恢复原课程，不丢聊天、页码和进度。

#### 真实模型兼容修复

真实 Codex → DeepSeek 调用暴露了单元测试中不会自然出现的输出变体，本轮均已添加验证与安全归一化：

- 选项有时返回 `"A. ..."` 字符串而不是对象：转换为小写 `id + label`，答案键同步归一化。
- `practice_path` 有时带 `main.go` 文件名：安全收敛到父目录，绝对路径或 `..` 仍会被拒绝。
- 评分有时返回 `0.85` 而不是 `85`：仅对 0–1 的小数安全转为百分制。
- `language` 有时表示内容语言而写成 `zh`：当主题明确是 Go/Python/Java/Rust 时归一化为该编程语言；真正的错语言课件仍拒绝。
- Go `for i := 0; i < n; i++` 中的英文分号不再被当成知识点分隔符。
