# Onboarding、研究校验与输入区修复设计

## 目标

修复三项已复现问题：生成进度第二行与第四行重复、不可依赖的语音入口长期展示、明确的“AI 前端面试 + 初学”意图被错误带向概念速学并在研究主题校验处失败。

## 设计

1. 进度卡保留两层信息：第二行是本次长任务的总体说明，生成期间不轮换；第四行只轮换当前子步骤。百分比、已等待时间和预计剩余时间继续独立更新。
2. 完整移除语音识别：删除麦克风按钮、浏览器语音初始化、独立脚本引用、样式与旧测试。输入区只保留发送按钮，避免展示无法稳定工作的能力。
3. 明确面试目标时，意图 Skill 将“通过目标岗位面试并完成模拟面试”视为可验收结果。`初学` 映射为 `level_claim=zero`，路线为 `interview_sprint`，`concept_scope=not_applicable`；不再询问“理解概念 / 掌握语法 / 完成项目”。
4. 研究文件的主题仍必须与课程主题一致，但校验会忽略括号中的路线说明，以及“工程师”等岗位后缀。匹配成功后将研究主题规范化为用户原始主题再保存；真正不同的主题仍拒绝。
5. `publish` 仍只负责把已验证的 `workspace/dev` 白名单内容复制成运行时快照 `workspace/releases/current`。它不是上传 GitHub，也不发布 npm/PyPI。

## 错误处理

- 意图模型输出仍必须经过结构化 Schema 校验。
- 研究主题只有在去除允许的展示性修饰后相同才放行，不能使用宽松包含匹配。
- 研究文件其他字段、引用关系、深度覆盖要求保持原校验。

## 验证

- 前端契约测试确认第二行不再随 phase 轮换，并且页面、脚本和样式中不存在语音入口。
- 意图 Skill 增加“我想面试 AI 前端，初学”评测场景；提示词增加明确约束。
- 研究单元测试复现带“工程师（面试冲刺 · 零基础）”修饰的主题并验证规范化，同时保留真正错题目的拒绝测试。
- 运行全量 pytest、前端语法检查、workspace 校验与 Git 差异检查后提交 GitHub。
