# 学习项目折叠、去重与删除设计

**状态：** 已实施并验证
**日期：** 2026-08-22
**范围：** 左栏项目入口、添加项目、同主题去重、项目删除、测试数据清理、共享教案保留

## 1. 目标

学习状态下，左栏的主要空间必须服务于完整课程大纲。学习项目不再常驻顶部占用高度，而是在左栏底部折叠；需要切换、添加或管理时再展开。

## 2. 信息架构

- 左栏顶部只保留紧凑品牌栏、当前计划标题和总进度。
- 中部由大纲与题库占据全部剩余高度，并独立滚动。
- 底部固定一行“学习项目 · N”，点击后向上打开浮层。
- 浮层列出当前项目和历史项目，并提供“添加学习项目”。
- 点击“添加学习项目”收起浮层，进入已有的自由输入 onboarding，不增加固定问题。
- 首次使用没有项目时，底部入口仍存在，显示“学习项目 · 0”。

## 3. 同主题项目

主题键使用 Unicode 规范化、大小写折叠、去除多余空白和常见标点。`LangGraph`、`langgraph` 与 `Lang Graph` 视为同一主题。

在意图 Skill 返回 `ready_for_plan` 后、建立新项目快照前，后端按主题键查找现有项目：

- 没有匹配：继续生成新 Plan。
- 有一个匹配：不创建副本，在输入框上方提示“已经有这个学习项目”。
- 可选择“继续已有项目”或“把新目标合并到已有项目”；输入框仍可直接改成其他主题。
- 如果历史数据已经存在多个同主题项目：选进度最高、其次更新时间最新的项目作为主项目；合并问题、笔记、错题和复习卡等可追加记录；冲突的课程状态不盲目拼接；其余副本从可见列表移除并保留可恢复备份。

## 4. 删除交互

桌面端右键、触屏长按和移动端左滑都打开同一个项目操作层，不各自实现不同删除逻辑。

- 右键：阻止浏览器默认菜单，显示项目菜单。
- 长按：按住约 600ms 后显示菜单，移动超过阈值则取消。
- 左滑：超过 64px 后露出删除操作。
- 所有入口最终都进入原生 `<dialog>` 风格的确认框。
- 确认框显示项目名，并明确“删除个人计划、进度、笔记与作业；共享知识库教案不受影响”。
- 删除当前项目后回到空白 onboarding；删除历史项目不影响当前课程。

## 5. 后端边界

Python负责确定性数据操作：主题规范化、项目查重、项目列表、精确删除、当前项目清空和可恢复归档。Codex Skill仍负责理解用户到底想学什么、是否属于同一语义主题以及怎样调整目标。

项目删除 API 必须校验 `user_id` 与 `project_id`，只能操作该用户目录内的 `current` 或合法归档 ID。删除共享 `workspace/**/curriculum` 的路径永远不进入该 API。

## 6. 用户数据清理

功能验证完成后，把 `learning-agent-server/userdir` 整体移动到 macOS 废纸篓中的时间戳备份，再创建一个空的 `userdir`。同时通过前端数据版本清除旧聊天缓存，使页面从首次使用状态开始。

保留：

- `workspace/dev/curriculum/generated/`
- `workspace/releases/current/curriculum/generated/`
- Skills、课程原子、发布版本和项目源码

清除：

- 用户画像、Plan、进度、对话历史、作业、错题、复习卡
- 当前项目、项目快照与项目归档
- 用户运行时目录和练习目录

## 7. 知识库现状

完成章节后，系统会把验证过的讲义、答案、Markdown 原子和 HTML deck 写入 `workspace/dev/curriculum/generated/`。当前开发知识库已有 Go 与 RAG；正式发布副本目前只有 RAG。本次数据清理不触碰这些目录。

## 8. 验收

1. 学习界面左栏顶部不再显示项目列表，大纲获得主要高度。
2. 底部项目入口可展开、切换和添加项目。
3. 右键、长按、左滑都能触发删除，并且删除前必须确认。
4. `LangGraph` 与 `langgraph` 不会创建两个项目。
5. 已有同主题项目时，onboarding 提示继续或合并目标。
6. 删除当前项目后安全回到首次输入界面。
7. 用户目录清空，页面无旧对话；共享 Go/RAG 教案仍存在且校验通过。
