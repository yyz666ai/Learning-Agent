# Agentic 意图识别与建档设计

**状态：** 已确认，进入实施
**日期：** 2026-08-22
**范围：** 首屏历史项目、自由输入、多轮意图识别、slot filling、动态追问与紧凑选项

## 1. 目标

用户打开网页后可以直接从左栏继续任意历史学习项目，或在唯一输入框中自由说明当前需求。系统不再先展示固定路线表，而是让 Codex 根据 Skill、最近对话与已有用户状态理解意图。

## 2. 首屏

- 桌面端一直保留左侧“学习项目”栏，列出当前与历史项目、进度和最近学习时间。
- 点击项目直接恢复对应大纲、PPT 和进度，不经过“继续上次”对话选择。
- 主区只问“你现在想解决什么？”，不预置语言或目标选项。
- 手机端左栏收进抽屉，不挤占对话。

## 3. 多轮 Slot Filling

`slot filling` 不是一次性表单。每轮都把“新一句话 + 最近对话 + 当前槽位状态”交给 Codex，它可以填充、修正或删除槽位。

### 3.1 槽位

| 槽位 | 用途 |
| --- | --- |
| `intent_family` | 新学习、当前答疑、面试题入库、复习、看懂项目等 |
| `topic` | 学习对象，保留用户原意 |
| `goal` | 这次真正要解决的问题 |
| `desired_outcome` | 最后要会做什么 |
| `target_context` | 面试岗位、项目、API、业务场景或交付物 |
| `level_evidence` | 用户自述和对话中已表现的能力，不直接当长期掌握证据 |
| `deadline` | 只在用户提到或确实改变路线时使用 |
| `learning_scope` | 了解概念、看代码、系统掌握、项目交付等实际范围 |
| `constraints` | 时间、技术栈、已有项目和其他约束 |

### 3.2 每轮决策

Codex 只能返回四种行动：

- `clarify`：缺一个会真正改变 Plan 的槽位，只问这一个问题。
- `ready_for_plan`：信息足够，生成计划草案。
- `answer_in_context`：这是当前课程答疑或一次性故障，不新建学习项目。
- `interview_bank_intake`：用户在提交面试题，转入题库流程。

### 3.3 追问规则

- 已有槽位不重复问；新输入可显式修正旧槽位。
- 一次只问一个问题。信息仍不足可以继续追问，但不得重复已填槽位；一旦足以生成可验收的 Plan，立即停止追问。
- 每题由模型根据主题生成 2–3 个选项，不展示“其他”“都不符合”或“我直接补充”按钮。
- 输入框始终可用；用户直接输入并 Enter 即可取代选项、补充或修改需求。
- 不因为后端有默认字段就反向追问用户。

## 4. 结构化输出

```json
{
  "action": "clarify",
  "confidence": 0.87,
  "summary": "用户要准备 Java 后端面试",
  "slots": {
    "intent_family": "interview_preparation",
    "topic": "Java 后端",
    "goal": "面试冲刺",
    "desired_outcome": "稳定回答 JVM、并发和项目追问",
    "target_context": null,
    "level_evidence": null,
    "deadline": "7 天",
    "learning_scope": "interview",
    "constraints": []
  },
  "question": {
    "prompt": "Java 后端你目前大概到哪一步？",
    "slot": "level_evidence",
    "options": [
      {"id": "a", "label": "只会基础语法", "detail": "项目经验较少"},
      {"id": "b", "label": "做过普通项目", "detail": "能写业务代码，原理不够稳"},
      {"id": "c", "label": "有线上经验", "detail": "重点练架构和故障追问"}
    ]
  },
  "onboarding": null
}
```

`ready_for_plan` 时，`onboarding` 必须给出经模型判断的 `goal_route`、`learning_mode`、`level_claim`、`concept_scope` 和合理内部时间预算。Python 只验证枚举、数量、字段长度和状态一致性，不根据关键词替模型选路线。

## 5. 历史对话

- 意图识别只携带当前 onboarding 的最近 8 条消息和当前槽位，不扫描所有用户历史。
- 选项点击也记为一条用户消息，下一轮 Codex 可以联合判断。
- 用户说“不对，我其实只想…”时，新输入优先于旧槽位。
- 切换历史项目后使用该项目自己的对话与学习状态，不混入另一个项目。

## 6. 选项界面

- 按钮只常驻显示序号、短标题和右侧信息图标。
- `detail` 放在 tooltip：鼠标悬停、键盘聚焦或手机点击图标时显示。
- 选项一般 2–3 个，总数不超过 3；详细说明不占据卡片高度。
- 点击后立即显示选中态和动态判断反馈，不让用户猜测是否已生效。

## 7. 失败与安全

- 模型输出不符合 Schema、超过 3 个选项、重复问已填槽位或 `ready_for_plan` 缺少 onboarding 数据时，服务端拒绝该结果。
- 模型不可用时保留输入和槽位，显示重试；不回退到固定七选项。
- 外部文本只是待分析数据，不能覆盖 Skill 与系统边界。
- 只有用户确认 Plan 后才切换活动学习项目；意图分析失败不修改原课程。

## 8. 验收场景

1. 旧用户打开网页：左栏可直接点击历史项目，对话不显示“继续”选择。
2. “RAG 是什么”：识别为概念需求，不问每日时长。
3. “下周面试 Java 后端，我做过两年项目”：复用已说明的期限和经验，不重复问。
4. “学 LangGraph”：只动态问一个会改变路线的问题。
5. 用户点了选项后又输入“不对，我只想看懂现有项目”：新输入修正旧槽位。
6. “这段代码为什么报错”：留在当前对话，不新建课程。
7. 粘贴一批面试题：转入面试题库。
8. 选项只有 2–3 个，无 D/其他选项，输入框在全程仍可 Enter 发送。

## 9. 2026-08-22 实施记录

- 新增 `learning-intent-router` Skill：定义可修正的多轮槽位、四类行动和动态追问边界。
- 新增 `/api/onboarding/intent`：每轮把最新输入、最近 8 条建档对话、当前槽位交给 Codex，并严格校验结构化结果。
- 删除前端本地关键词意图路由：页面不再加载 `topic-intent.js`，自由输入统一先经过模型意图判断。
- 首屏改成左侧历史学习项目 + 自由输入；历史项目直接点击恢复，不再在对话中提供“继续上次学习”。
- 追问选项压缩为 2–3 个短标题，详情放入可聚焦/可点击的 `i` tooltip；不生成 D、其他或“直接补充”。
- 输入框在追问阶段仍是直接修正入口，Enter 后携带已有槽位与对话继续判断。
- 追问不设置面向用户的固定轮数：只要真正影响 Plan 的信息仍不足，可以继续一次一问；不得重复槽位，信息足够必须立刻停止。
- 原课程直到 `ready_for_plan` 才建立安全快照；意图判断失败不会切换活动项目。
- 在已有课程中输入答疑时，讲义在意图判断期间保持可见；只有模型确认这是新学习且进入 `ready_for_plan` 后，界面才切到 Plan 审阅。
- 已增加后端 Schema、API、Skill 合同、前端合同和项目切换回归测试。

## 10. 2026-08-22 自然有机风与快速意图路由增量

### 10.1 初始页信息架构

- 初始页只保留左栏的一处 `Learning Agent` 品牌，不在对话顶栏重复显示 Agent 标识。
- 删除无实际动作的右上角三点菜单。对话顶栏只保留当前上下文、连接状态和移动端“学习项目”入口。
- 学习项目从左下角弹层迁移为左栏常驻列表；初始页优先展示全部历史项目，点击直接继续。学习页中列表限制高度，把主要空间继续留给大纲和题库。
- 左栏底部只保留紧凑的“设置与提醒”。添加项目使用学习项目标题旁的 `＋`。
- 手机端通过“学习项目”按钮打开同一左栏抽屉，不复制第二套项目数据和操作逻辑。

### 10.2 对话和选择题

- 用户消息位于右侧，仅显示消息正文，不再渲染“你”标签；宽度按内容收缩并限制最大宽度，避免短句形成大气泡。
- 对话输入区桌面最大宽度从 720px 提升到 900px，正文输入字号提升到 16px；手机端保持 44px 以上的语音和发送触控目标。
- 动态选择题继续由意图 Skill 生成 2–3 项，卡片与详情按钮统一置于输入框上方。标题常驻，详细说明只在悬停、聚焦或点击信息按钮时显示。
- 视觉系统统一为 Natural Organic：`#faf6f1` 暖米色背景、`#5c4033` 土棕主色、`#8b9d77` 鼠尾草绿强调、衬线标题、柔和不规则圆角、轻阴影和缓慢颜色过渡；不使用冷色霓虹、纯黑、重阴影或弹跳动效。

### 10.3 onboarding 性能策略

- 速度测试确认旧链路的单次“我想学 Go”意图判断约为 21.5 秒。原因不是 Flash 型号未生效，而是 DeepSeek V4 默认开启思考，并且请求还需要启动完整 Codex CLI、加载 workspace 和 Skill。
- onboarding 是范围明确的结构化路由任务：后端读取发布快照中的 `learning-intent-router/SKILL.md`，把完整 Skill 作为最高优先级 system 规则交给 `deepseek-v4-flash`，要求 JSON Schema 结构化输出，并显式传入 `thinking: {type: disabled}`。
- Python 仍只做边界工作：加载 Skill、发起模型调用、校验 JSON/枚举/选项数量和保持状态事务；主题、槽位、是否追问、选项内容和路线仍由模型依据 Skill 与多轮历史决定。
- 完整 Plan、权威资料研究、讲义生成、答疑和课程修订仍走 Codex Agent + workspace Skills；只对 onboarding 的短决策使用无思考 Flash 快路径。
- 修改后四类真实请求实测为 2.7–3.3 秒：RAG 概念、Java 面试、LangGraph 项目均直接进入 Plan；缺少项目信息的“看懂一个新项目”只追问一个关键问题。

### 11.1 统一对齐网格

- onboarding 的正文、动态选择题、错误状态和底部输入框统一使用一个居中的 `1040px` 内容列，不再分别设置 660px、780px、900px 等互相打架的宽度。
- 侧栏固定为 240px；右侧内容列按剩余空间居中。桌面实测正文和输入框均为 `left: 272px / right: 1248px / width: 976px`，水平溢出为 0。
- 用户消息继续在右侧按内容收缩，不显示“你”；Agent 正文保持左对齐，但其容器与输入框共用同一左右边线。

### 11.2 Corporate Clean 视觉系统

- 删除 Natural Organic 的米色、棕色、衬线标题和不规则 blob 圆角，改用 `#f8fafc` 浅灰背景、白色表面、`#2563eb` 主蓝、`#1d4ed8` 深蓝和 slate/gray 文本边框体系。

- 交互反馈限制在 150–200ms：悬停轻微上移并增强阴影，按下缩放到 98%，键盘聚焦使用蓝色焦点环与 2px offset。

### 11.3 图标与选择题

- 引入 Bootstrap Icons，替换 `LA`、`＋`、`•••`、`i`、`↑`、`×`、翻页箭头和设置按钮等文字模拟图标。

- 选择题宽度为输入框的 100%，详情说明只在悬停、键盘聚焦或点击图标时出现；输入框仍是自由修正需求的直接入口。

## 12. 2026-08-22 教学入口、Plan 稳定性与讲义渲染修正

### 12.1 模糊主题的三路意图识别

- 用户只输入“我想学 Go / Java / LangGraph”时，不再由模型猜测为后端、项目或某个固定方向，也不直接生成 Plan。
- `learning-intent-router` Skill 明确要求只出现三个第一层方向：`初学`、`精进`、`面试`。输入框始终保留为自由修正入口，不增加“其他”按钮。
- 初学下一问只确定想达到的深度；精进下一问只区分能力加深与看懂/修改现有项目；面试下一步邀请用户直接粘贴收集到的题目，再结合岗位和期限扩展题库。
- 如果用户原话已经明确“从零到工程师”“看懂项目”“准备面试”或“只理解概念”，跳过三路问题，直接填充槽位或只追问真正缺失的一项。

### 12.2 个性化 Plan 失败根因与处理

- 真实复现发现：完整 Go 计划和权威研究已经生成，但模型把 `prerequisites` 与毕业项目 `evidence` 写成分号分隔字符串；研究 Schema 只接受数组，导致最后的研究校验误判失败。
- 研究读取器现在把常见的分号/换行字符串规范化为数组，并兼容 `Go` / `Go 语言`、`RAG` / `RAG 是什么` 这类不改变主题的表述差异；来源 URL、事实引用、覆盖领域数量和毕业项目要求仍严格校验。
- API 现在区分模型超时、Plan 完整性失败、研究资料失败和课程树转换失败，返回可读原因；前端直接显示真实失败阶段，不再统一显示“模型没有生成合格大纲”。
- Plan 生成期间继续轮播“核对资料—排列顺序—检查遗漏—整理 Plan”的动态状态，失败时保留用户主题、选择和安全兜底计划。

### 12.3 HTML PPT 与左栏

- Markdown 中的 `mermaid` 围栏改为真正的 Mermaid 图，并在对话流、Plan、讲义页、作业页和题库答案的动态更新后重新执行渲染；普通代码围栏仍使用代码高亮。
- 初始讲义的“课程准备中”增加三点依次呼吸的动态省略号，并遵循 `prefers-reduced-motion`。
- 学习方案摘要从左栏顶部移到大纲/题库下方，默认折叠；只显示紧凑标题与总进度，展开后可查看时间和打开完整方案。大纲继续独立占据主要滚动空间。

### 12.4 回归验收

- 新增 Mermaid、动态等待、底部折叠 Plan、三路意图 Skill、研究字段规范化和模型超时分类测试。
- 全套自动化测试：281 项通过；发布 workspace 后结构校验为 0 错误、23 个 Skills、35 个知识概念。
