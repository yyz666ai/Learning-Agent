# Learning Agent 产品需求文档

> 版本：1.0  
> 更新日期：2026-08-24  
> 产品定位：以对话为入口、以个性化计划为主线、以真实练习与间隔复习为闭环的 Agentic AI 学习系统。

## 1. 产品愿景

Learning Agent 不是一次性问答工具。它要理解学习者的真实目标，制定可确认、可修改的学习计划，再用讲义、课堂检查、课后练习、答疑、复习和项目交付帮助学习者真正掌握知识。

系统同时维护可共创的教学 Skills 与知识库。经过验证的讲解、题目、误区和案例可以成为后续课程的可靠材料，减少重复生成并提高教学质量。

## 2. 目标用户

1. 只想快速弄懂一个概念的学习者。
2. 从零开始学习语言、框架或技术领域的小白。
3. 有一点基础，需要补齐薄弱点的学习者。
4. 想看懂、接手或改造现有项目的工程师。
5. 想通过真实项目达到工程能力的实践者。
6. 想从中级进阶到高级工程师的开发者。
7. 准备面试，已有题库或尚未收集题目的候选人。

## 3. 核心原则

- 对话优先：用户直接说目标，系统不先展示固定大表单。
- 少问快教：只追问会改变计划的缺失信息，一般 1–2 轮即可开始。
- 计划先确认：生成完整 `plan.md`，用户确认后才进入课程。
- 小步可验证：复杂知识逐页讲，课堂用点击题检查理解。
- 课堂与课后分离：课堂选择题用于消化；课后练习用于独立完成。
- 真实实践：代码课程建立可运行项目，示例包含清晰中文注释。
- 证据驱动：做对一道选择题不等于完全掌握；掌握需要独立实践和延迟复习。
- 复习有来源：每张复习卡必须来自课堂题、错题、作业、面试题或重要问题。
- 知识库审慎生长：个人内容先进入候选区，复核后才能进入公共知识库。

## 4. 产品信息架构

### 4.1 初始界面

- 左侧：历史学习项目，可继续、添加或删除。
- 主区域：Codex 风格对话。
- 输入框：接受概念、项目、面试、代码、题目或自然语言目标。
- 选择题：只在需要补齐关键信息时显示在输入框上方，每轮 3–4 项。

### 4.2 学习界面

- 左侧上部：可折叠学习项目。
- 左侧主体：课程大纲与当前位置。
- 左侧题库：课堂题、作业、补充练习和面试题。
- 中间：HTML PPT，可独立滚动、翻页和调整宽度。
- 右侧：持续对话、答疑、修改计划或要求重讲。

## 5. 核心功能

### 5.1 Agentic Onboarding

系统对首次自由输入执行意图识别与 slot filling，结合最近多轮历史维护以下槽位：

- 学习主题 `topic`
- 最终目标 `desired_outcome`
- 学习范围 `learning_scope`
- 当前水平 `level`
- 使用场景 `goal_route`
- 可用时间 `session_minutes`
- 项目或岗位上下文 `project_or_role_context`
- 面试目标岗位 `target_role`
- 面试技术栈 `tech_stack`
- 面试题来源 `interview_question_source`
- 已入库真实题数量 `interview_question_count`

只有缺失槽位会实质改变课程时才继续追问。用户可随时直接打字修正选择。

面试路线按“基础证据 → 技术栈 → 真实题来源”补槽；每轮仍只问一个问题。用户有小红书、面经或 JD 中收集的题时，必须先完成入库再生成 Plan；没有现成题时，按完整岗位与技术栈做权威资料研究后生成 Plan。

### 5.2 个性化 Plan

Plan 必须包含：目标、当前水平、最终达成标准、知识覆盖地图、章节、知识点、课堂练习、课后练习、复习策略、预计时间和最终项目。

- 概念速学：短计划，不强制每日时长和长期复习。
- 完整掌握：由浅入深覆盖基础、机制、调试、测试、工程、安全、性能和大型项目。
- 项目路线：围绕真实代码入口、调用链、修改点和交付目标组织。
- 面试路线：知识体系、口头表达、追问、代码推演和模拟面试并重。

Plan 在对话中以 Markdown 渲染。用户确认后锁定当前版本；修改计划不得清空已取得进度。

### 5.3 自适应 HTML PPT

- 页数由知识密度决定，不按固定模板机械切页。
- 支持 Markdown、代码高亮、Mermaid、重点加粗与高亮。
- 代码内容必须进入代码框并带中文注释。
- 初学者课程必须包含环境安装、运行命令和常见配置问题。
- 每页直接写明本页要理解或操作什么，不使用遮挡输入框的长期提示。
- 最后一页汇总本课收获、课后练习目录和下一章入口。

### 5.4 课堂与课后练习

- 课堂：以点击选择题为主，简单知识点做对后快速推进。
- 课后：用户在真实项目中独立编写或修改代码，最多给 3 条递进提示。
- 用户可以把代码、结果或问题发回对话框，不设置繁琐的固定输出验收框。
- 重点问题、错误和教练总结自动写入个人笔记，并可形成复习卡。

### 5.5 统一练习题库

题库统一收录：

- 课堂选择题；
- 课后作业；
- 用户要求追加的针对性练习；
- 用户收集或系统生成的面试题；
- 对话中标记为重要的知识问题。

每一题记录来源、题型、题干、选项或参考答案、知识点、作答历史、错误次数、掌握状态、上次复习时间和下次复习时间。

### 5.6 Anki 式复习中心

题库底部提供“开始复习”按钮。复习会话按以下顺序选择最多 5 题：

1. 已到期且做错过的题；
2. 已到期的面试题；
3. 已到期的普通题；
4. 尚未复习的新题。

卡片交互：

1. 正面只展示问题，避免提前泄露答案。
2. 用户口述、思考或在对话框作答。
3. 点击“查看答案”后展示参考答案、解析、上次错误和关联知识。
4. 用户选择“没想起来 / 稍微有点困难 / 顺利”。
5. 后台分别安排 1 / 3 / 7 天后复习，并累计历史记录。

复习按钮显示“今日到期 N 题”。没有到期题时，可选择复习错题或随机巩固，但不得伪造掌握进度。

### 5.7 对话追加练习

用户说“再出几道题”“针对这个多练练”时，系统读取当前主题、知识点、最近错误和目标难度，调用 `practice-drill` 与 `quiz-designer` Skill 生成 3–5 道题。

- 题目必须带答案和解析；
- 选择题答案必须属于选项；
- 不得重复已有题；
- 生成成功后自动进入统一题库；
- 当前 HTML PPT 已打开时，把题目作为可点击的 `check` 页面插入总结页之前，并自动定位到第一道新题；同时注册到统一题库。
- 没有活动讲义时只进入题库并打开复习；前端明确提示新增数量和落点。
- 内容生成必须通过项目配置的 Codex harness 读取 `practice-drill` 与 `quiz-designer` Skills；Python 只负责结构校验、原子保存和确定性判分。

### 5.8 面试学习

#### 用户有面试题

保留原文、拆题、去重、分类，并询问逐题讲、系统学习或先测后学。系统为缺失答案的题生成参考答案、评分标准、常见遗漏和相关追问。

#### 用户没有面试题

如果最终目标是面试，系统不得等待用户上传题目。每章末尾自动生成 2–4 道岗位相关简答题，包含：

- 问题；
- 30–90 秒参考回答；
- 回答结构；
- 常见遗漏；
- 1–2 个追问及答案要点。

问题先在 PPT 中显示，答案点击后展开，并同步进入面试题库。课程末尾安排一轮模拟面试。

### 5.9 学习进度与证据

进度按完成的知识点与课程证据计算，不按打开页面计算。题库掌握率独立显示，不能替代课程进度。

### 5.10 用户目录、项目隔离与记忆

每个本地使用者的数据都保存在 `userdir/u_<user_id>/`，不进入公开仓库。当前事实与变化历史分开保存：

- `profile.json`：稳定画像和已确认的 onboarding 槽位；
- `onboarding/intent-state.json`：可恢复的当前 slot filling 状态；
- `onboarding/intent-events.jsonl`：每轮意图、证据、选择和纠正历史；
- `memory/conversation-events.jsonl`：需要长期保留的用户与 Agent 对话事件；
- `profile.md`、`plans/*.md`：供用户阅读，也供后续 Agent 在最小范围内读取。

每门学习项目的归档快照同时包含画像、onboarding、Plan、课程、题库、复习、面试题和真实 `projects/` 练习目录。切换项目必须整体恢复，不能让两门课程混用题库或代码目录。浏览器 `localStorage` 只作界面缓存，不是学习记忆的唯一来源。

掌握状态：`unseen → introduced → practicing → provisional → mastered`。遗忘或重复错误进入 `needs_review`。

### 5.11 知识库自生长

- 模型生成且通过结构校验的讲义可进入课程缓存。
- 重要问题先进入 `curation/pending/`。
- 候选内容必须验证事实、来源、可运行示例和教学效果。
- 复核后才能合并成公共知识原子或题库资产。
- 用户学习记录、答案和隐私内容永不进入公共知识库。

### 5.12 流式与等待反馈

对话使用 FastAPI SSE 流式返回。Plan、讲义、练习和评价等长任务必须展示当前阶段、动态进度和预计剩余时间；预计时间是基于历史阶段耗时的估计，不冒充精确完成时间。

## 6. 非功能要求

- 本地优先：密钥与学习数据留在本机。
- 可恢复：生成失败不覆盖旧计划或现有课程。
- 可访问：键盘操作、可见焦点、ARIA 标签和 reduced-motion。
- 安全：路径限制在用户目录，模型结构化输出必须校验。
- 性能：确定性判题与题库读取不调用模型；只有生成新内容、复杂评价和讲解时调用模型。

## 7. 核心数据对象

### PracticeItem

`id, source, kind, topic, knowledge_point_id, prompt, options, answer, explanation, status, attempts, wrong_count, needs_review, last_reviewed, next_review`

### ReviewAttempt

`rating, answer_snapshot, correct, reviewed_at, next_review, interval_days`

### InterviewQuestion

`id, origin, role, domains, prompt, answer_markdown, rubric, follow_ups, mastery, evidence, next_review`

## 8. 验收标准

1. 一节课生成后，课堂题和课后作业能在题库看到。
2. 题库底部存在“开始复习”，并显示到期数量。
3. 复习先显示问题，点击后才显示答案。
4. 三档评价会持久化并产生不同复习日期。
5. 刷新网页后，复习历史和下一次日期仍存在。
6. 对话要求追加练习后，新增题自动出现在题库。
7. 面试路线即使没有用户题目，也会产生带答案的章末简答题。
8. 所有生成选择题经过答案交叉校验。
9. 所有代码型课程的示例包含中文注释。
10. 全部自动化测试和 Workspace 校验通过。
