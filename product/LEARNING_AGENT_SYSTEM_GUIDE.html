01

产品定位

Learning Agent 不是普通聊天机器人，也不是把一套固定网课换成聊天界面。

面向谁

计算机学习者：零基础、本科课程学习者、有一点基础者、项目导向者、进阶工程师和面试准备者。

解决什么

把“我想学什么”变成可确认的学习路线，再通过完整章节讲义、课堂选择题、真实代码练习、答疑和复习持续推进。

核心差异

教学内容由共享知识库提供可靠事实，Skills 决定怎么教，Agent 处理个性差异，Python 保证状态、路径、判分和事务可靠。

一句话定位：一个会记住学习者、能够生成并调整课程、能在真实项目中带着练习、并把优质教学持续沉淀回知识库的个人计算机学习系统。
版本用户付费的是什么知识内容模型数据
本地开源版免费开放知识库与 Skills用户自己配置 API本机用户目录
云端学生版云同步、托管 Agent、免配置模型、跨设备体验同一公共知识库由平台选择并控制额度云端同步，手机与电脑共享

05

意图识别与 Onboarding

第一个输入框接受自然语言。左侧项目负责继续历史学习，输入框负责新目标和当前答疑。

1. 用户自由输入

例如“我想从零学 Go”“两天看懂 LangGraph 项目”“我要准备 AI 前端面试”。前端不会先让用户从固定语言列表里选一个。

2. Flash 意图路由

/api/onboarding/intent 读取 learning-intent-router Skill，将最近对话、已有 slots 和当前消息交给 DeepSeek Flash，关闭思考模式，要求返回结构化 JSON。

3. Slot filling 与语义校验

主题、路线、水平证据、技术栈、面试题来源等逐步补齐。Python 检查模型不能凭空猜水平、不能偷偷换主题、不能把岗位题变成无关语法题。

4. 只追问关键缺口

需要确认时，在输入框上方显示 2–3 个紧凑选项；用户仍可直接输入补充。零基础通常不做诊断，学过一点或熟练者使用 3–4 道点击题。

5. 建档落盘

确认后写入 profile.json、profile.md、learning-state.json 和初始 Plan 草案，并为这轮生成创建 generation id。

Slot filling 当前保存在哪里？

onboarding/intent-state.json 保存当前槽位事实；onboarding/intent-events.jsonl 追加每轮输入、决策和纠正历史；确认后的稳定画像进入 profile.json，人类可读版进入 profile.md。

面试路线有什么额外步骤？

目标岗位明确后，应补齐主要技术栈，并询问用户是否有从小红书、面经或 JD 收集的真实题目。有题先进入 Interview Bank，再据此构建针对性 Plan；没有题则使用知识框架与经核验资料继续生成。

06

Plan 生成与确认

Plan 是课程合同，不是开场白。当前实现由 Codex 生成，再由 Python 严格校验和保存。

前端
确认建档→动态等待→对话式渲染 Plan→确认 / 输入修改意见
FastAPI / Python
生成 lease→组装 prompt→校验结构与主题→解析 Curriculum→原子保存
Codex / Skills
learning-plan→必要时研究新主题→输出完整 Markdown
用户目录
plans/*.md+curriculum.json+learning-state.json

Python 校验什么

  • Plan 必须提到当前主题；
  • 必须有“当前任务、学习成果、教学策略”；
  • 不同路线的阶段数必须合理；
  • 每阶段必须有学习内容、练习和完成证据；
  • 完整掌握路线必须有知识覆盖地图、毕业标准和毕业项目；
  • 迟到的旧生成结果不能覆盖新项目。

用户怎样修改

Plan 作为普通 Agent 消息显示。用户不需要点击“我要调整”，直接在聊天框说“前面快一点”“加上 TypeScript”“毕业项目换成客服 Agent”，系统调用 plan-revision Skill，保留已完成进度。

当前 Plan 仍主要依赖模型生成
07

HTML PPT 教学工作流

Plan 确认后才生成第一章。每次生成的是完整当前章，而不是做一道题又重新生成同一章。

读取 Curriculum当前章与剩余知识点
查整章缓存主题、路线、层级和范围完全匹配
调用 Codexadaptive-lesson-flow + 内容 Skill
结构校验页数、答案、代码注释、范围证据
建立练习目录projects/<课程项目>/...
前端渲染Markdown、代码高亮、流程图和进度
课堂选择题点击后确定性判分
完成本章题目入库、推进下个知识点

页面密度

简单内容 4–8 页；普通章节 8–16 页；概念密集或存在误区时可到 12–24 页。页数由教学密度决定。

代码要求

代码必须进入独立代码框、支持复制反馈；面向初学者时逐步搭建并提供清楚的中文教学注释。

最后一页

展示本章总结、完整运行代码、项目路径、课后练习和明确下一步；不能让用户翻完后不知道做什么。

用户不满意 PPT 时现在能不能直接修改？

可以。右侧聊天框识别“太浅、太长、图少、代码看不懂、重新讲”等请求，通过 /api/lesson/remediate 调用 lesson-revision Skill。新版本只有通过校验后才替换旧课件。

能不能在 PPT 后面追加练习？

可以。前端请求 /api/practice/supplemental/generate，读取 practice-drill 与 quiz-designer Skills。传入 append_to_lesson=true 时，练习会追加到当前 Lesson；否则只进入题库并打开复习。

08

课堂、作业、题库与复习

四者共用知识点关联，但承担不同目的。

课堂选择题

放在 PPT 内，直接点击，验证刚讲过的关键判断。答案保存在私有 answers 文件，不随公开 Manifest 下发。

课后作业

留在真实项目目录供用户自主完成，不反复要求输入解释，也不作为课堂推进强制门禁。

统一题库

课堂题、错题、作业、追加练习和面试题进入 practice-bank/items，记录次数、错因和状态。

Anki 式复习

揭示答案后选择“没想起来 / 有点困难 / 顺利”，当前间隔分别为 1、3、7 天。

确定性优先：选择题由 Python 根据私有答案键判分；翻页、显示进度、题库筛选和复习调度不需要每次调用大模型。自由作业批改或开放回答才需要模型。
09

右侧聊天框的作用

聊天框是统一的自然语言控制面，而不是另一个课程页面。

学习答疑

发送报错、代码、概念疑问或项目问题。FastAPI 通过 SSE 流式返回 Codex 回答，并将重要问题总结到本课笔记。

控制学习产物

可以直接说“修改 Plan”“重做这份讲义”“多出三道题”“换个例子”，系统根据意图进入对应接口与 Skill。

形成个人记忆

成功对话写入 memory/conversation-events.jsonl；问题进入问题记录，关联课程时还会写入专属课堂笔记和复习材料。

聊天框不应该承担所有确定性工作。选择题判分、项目切换、进度推进、文件路径安全和复习调度继续由 Python 负责，否则会变慢、变贵，而且容易出现不一致。
10

Agent Harness 是怎么搭建的

Harness 是把网页、用户状态、Codex CLI、Skills、模型和文件权限连接起来的运行外壳。

浏览器
输入 / 点击→Fetch / SSE←消息、进度、PPT
FastAPI 桥
校验请求→读取用户状态→组装 Prompt→事务保存
Codex Harness
spawn codex exec --json→cwd = release 快照+CODEX_HOME = 用户运行时+USER_DIR = 可写区
模型与知识
DeepSeek Provider+AGENTS.md+.codex/skills+curriculum

① cwd：稳定教学快照

Codex 在 workspace/releases/current 中运行，自动读取其中的 AGENTS.md 和 Skills。运行态不直接依赖正在编辑的 dev 文件。

② CODEX_HOME：每用户运行时

每个用户拥有独立的 .codex-runtime/home，从模板复制 DeepSeek Provider 配置，与开发者个人 ~/.codex 分离。

③ USER_DIR：业务可写区

用户画像、Plan、课程、题库、对话记忆和项目都写到自己的 userdir/u_<id>，不会写进共享发布快照。

两条模型调用路径

路径适用任务是否读取完整 Agent Workspace当前实现
Codex Harness自由答疑、诊断生成、Plan、Plan 修订、课件、讲义修订、追加练习是。通过 cwd 自动读取 AGENTS 与 Skillscodex_driver.py 启动 codex exec --json
DeepSeek 直连低延迟结构化意图、部分即时判题/生成否。由 Python 显式注入所需 Skill 文本或 system promptllm.py 调用 OpenAI 兼容接口；意图使用 Flash、非思考、JSON 模式
当前安全现实：本地 MVP 默认仍可使用 danger-full-access，主要依靠目录分离、只读发布快照和 AGENTS 红线约束。生产云端应升级为容器、只读挂载和最小写权限，不能只依靠提示词。
11

Skills 体系

Skill 管“怎么判断、怎么教、怎么互动”，知识库管“知识事实是什么”。修改 Skill 后，下一次发布快照中的 Agent 行为会随之变化。

建档与规划

  • learning-intent-router：自由输入、意图识别和 slot filling；
  • learner-onboarding：建档总流程；
  • adaptive-onboarding：3–4 道能力诊断；
  • learning-plan：生成可确认 Plan；
  • plan-revision：按聊天意见修订 Plan；
  • codebase-learning-plan：从真实项目反向规划。

教学与呈现

  • adaptive-lesson-flow：完整章节 PPT 合同；
  • concept-teaching：概念直觉与边界；
  • progressive-code-teaching：长代码渐进搭建；
  • code-learning：文件、函数和调用链；
  • environment-setup：零基础环境页；
  • visual-explainer：Mermaid 和关系图。

练习与反馈

  • quiz-designer：可点击课堂题；
  • practice-drill：针对性刷题；
  • project-practice：用项目进行练习；
  • exercise-coach：分级提示；
  • assignment-review：代码和作业批改；
  • spaced-review：到期复习；
  • learning-progress：进度、薄弱点和下一步。

生成、修订与知识生长

  • project-scaffolder：建立课程项目结构；
  • lesson-revision：重做当前课件；
  • new-topic-research：陌生或版本敏感主题研究；
  • knowledge-curator：把可复用内容沉淀为候选知识；
  • code-learning 与项目 Skill 共同保持目标代码只读边界。
修改 Skill 后会立刻生效吗？

开发母本在 workspace/dev/.codex/skills。当前 Codex 读取的是 workspace/releases/current/.codex/skills。因此修改后需要先通过校验和测试，再运行发布流程生成新的 current 快照；下一次 Codex 任务才会读取新规则。

所有流程都是每一步调用一个 Skill 吗？

不是。Skill 只在需要模型判断或生成教学内容时发挥作用。确定性判分、翻页、状态推进、项目切换、文件保存、缓存命中和复习时间计算不会为了“显得 Agentic”而重复调用模型。

Skill 和 Script 的关系

Skill 可以规定“先研究权威资料”或“建立项目骨架”，并允许调用受控 Script 完成搜索、验证或机械任务。Script 做可重复、可测试的动作；Skill 决定什么时候需要这个动作以及如何解释结果。

12

为什么还需要 Python 工作流

这仍然是 Agentic AI。Agent 负责开放决策，Python 负责不能靠“语言感觉”处理的产品事实。

Python 模块主要职责为什么不交给模型
main.pyFastAPI 路由、请求校验、SSE、协调各服务网络协议和接口合同必须稳定
codex_driver.py启动 Codex、注入目录与密钥、解析 JSONL 事件进程、环境变量和超时需要确定性控制
learning_intent.py结构化槽位、证据校验、主题稳定性防止模型猜水平或换主题
onboarding.py画像、初始 Plan、生成 lease 与状态写入刷新后必须保持一致
learning_plan_personalizer.pyPlan prompt、结构验证、状态转换无效 Plan 不能进入课程树
curriculum.py将 Plan 转成章节与知识点图课程推进需要稳定 ID
lesson_generator.py课件解析、答案交叉校验、范围修复防止漏答案、代码无注释和课程漂移
lesson_progression.py课堂完成判定和下个知识点不能让模型随意跳章或循环
practice_bank.py题库、答题记录和 Anki 调度判分与日期计算应确定
project_snapshot.py项目快照、切换、删除与回滚避免课程和题库跨项目混用
generation_transaction.py并发生成、取消、旧结果隔离防止迟到请求覆盖新学习项目
knowledge_library.py保存和复用已验证整章资产缓存键和版本匹配必须精确
user_memory.py当前画像和 append-only 事件记忆必须可追踪而非只存在上下文中
推荐边界：模型决定“教什么、怎么讲、该问哪个关键问题”；Python 决定“能不能保存、答案是否存在、路径是否安全、状态推进到哪里、旧请求是否失效”。

为什么同时使用 JSON、JSONL 和 Markdown

格式用途例子设计理由
JSON当前事实、可覆盖状态profile.json、learning-state.json、curriculum.json读取快、结构明确、适合校验
JSONL事实怎么变化、事件历史intent-events.jsonl、conversation-events.jsonl只追加、可追踪、单条损坏影响小
Markdown给人阅读和修改的内容profile.md、plan.md、知识原子适合 Git、PR、审核和共创
HTML / Manifest课程演示与交互Lesson JSON、导出的 deck前端可以稳定翻页、判题和显示代码
隐私边界：userdir/、密钥、真实对话和用户作业不进入 GitHub 或共享知识库。只有去隐私、可复用、经用户明确同意并审核的内容，才可能进入公共 curriculum。

可靠性、安全与失败恢复

Learning Agent 不只要“能生成”，还必须保证失败时不破坏已经学到的内容。

生成隔离

每轮 Plan 有 generation id 和项目 guard。用户切换项目或取消后，迟到结果被丢弃，不能覆盖当前课程。

原子写入

重要 JSON 先写临时文件，再替换正式文件；题库整课注册和项目切换有备份与回滚。

结构合同

Plan、Lesson、答案键、路径、范围证据和代码注释均有校验；模型格式漂移先修复，仍不合格则保留旧数据。

失败场景用户看到什么系统必须保留什么
意图识别失败可以重试，原输入仍在已有槽位和旧项目
Plan 生成失败显示明确失败阶段初始安全 Plan、画像、意图状态
课件生成失败重试按钮与可读错误当前章节、页码、题库和旧课件
项目切换失败仍停留在原项目原画像、Plan、课件、题库、项目文件
SSE 连接中断重连提示，已输入内容不消失用户消息、已完成事件和学习状态

云端同步与知识共创的演进

当前文件型架构适合本地 MVP。云端版需要把同样的边界映射到数据库和对象存储，而不是推翻 Agent 设计。

未来云数据实体

  • 用户与订阅：users、subscriptions、usage_ledger；
  • 学习项目：learning_projects、profiles、plans、curricula；
  • 课程：lessons、lesson_pages、lesson_versions；
  • 练习：practice_items、attempts、review_schedules；
  • 记忆：conversation_events、learner_memories；
  • 知识库：knowledge_atoms、atom_versions、kb_releases；
  • 共创：contributions、reviews、reward_ledger。

云同步原则

  • 服务端是多设备事实源，客户端保留离线缓存；
  • 事件用 append-only id 和时间戳增量同步；
  • Plan、课程和知识原子都有版本；
  • 用户进度不因知识库升级而重置；
  • 大型依赖和构建产物不进入同步；
  • API 使用按人民币成本记账，额度用完只停止新 AI 生成。

知识共创工作流

改进本页经验、讲解、题目或作业

自动校验隐私、来源、代码、答案、重复

verified进入版本化知识库
贡献奖励署名、积分、AI 额度和悬赏
推荐商业闭环：公共知识库开放共创；本地版免费自带 API；云端版按月或按年收取同步和托管 Agent 服务费。首版贡献奖励以 AI 额度、会员时长和任务悬赏为主，不承诺永久版权分成。

方案 B 的目标演进

当前是“知识原子雏形 + 整章缓存 1.0”；目标是“原子编译 + Plan/Lesson Composer + 用户 Overlay 2.0”。成熟后，大部分 Plan 和公共章节可以直接组合，模型只处理真正个性化的解释、私人项目和新知识缺口。

目标

Atom Compiler

把 Markdown 原子编译成定义、图、代码、题目等可复用 Blocks。

目标

Plan Composer

基于概念图、诊断和目标确定性组合大纲。

目标

Lesson Composer

按用户水平选择讲解变体和练习密度。

目标

User Overlay

只保存用户专属问题、笔记、例子和补充页。
