# 产品变更记录

## 2026-08-26

- 新增单文件《Learning Agent 产品与系统总说明》HTML：从产品定位开始，统一说明不同用户路线、Onboarding、Plan、HTML PPT、题库复习、聊天答疑、Codex Harness、Workspace Skills、Python 职责、用户目录、前后端 API、修改决策、安全恢复以及云同步和知识共创演进，并明确区分当前实现与目标方案。

## 2026-08-24

- 新增《知识库、个性化课件与降本架构设计》：完整盘点现有知识原子和整章缓存，确定采用“知识原子 + 自动编译 + Plan/Lesson Composer + 用户 Overlay”方案，明确个性化维度、Markdown 与 HTML 的单一事实源关系、Token 节省测算、分阶段迁移、测试指标及 ¥30/月或 ¥199/年的云端收费边界。
- 新增《年度成本与完整执行工作流》：同时按 DeepSeek 当前官网价和保守高峰价计算轻度、本科常用、重度与压力用户的年度 API 成本，给出阿里云部署区间，并逐步标明前端、Python、Codex harness、Skills、Scripts、知识库和用户目录的职责与调用时机。
- 修复中文研究主题的目录碰撞：`AI前端`、`AI后端`、`AI产品` 不再全部折叠为 `research/ai/`；新路径保留 Unicode 可读主题并加稳定哈希。
- 研究校验可从 Agent 旧的自定义目录中找回“主题精确匹配”的 `sources.json` 并迁移到标准位置；相似目录中的其他主题不会被误用。
- Plan 失败时后端现在记录精确阶段、用户、主题和完整异常栈，不再只向前端返回笼统的“结构检查没通过”。
- Plan 与 HTML PPT 生成新增项目级事务隔离：每轮生成绑定唯一 generation ID，模型结果先校验、后提交；恢复旧课程、切换项目、取消或重复生成后，迟到结果会被安全丢弃，不能再覆盖当前学习项目。
- 前端取消或恢复课程时会先通知后端取消当前生成租约；等待上限与后端保持一致，不再出现前端五分钟先报失败、后端十分钟后又写回的竞态。
- Plan 文件名改为 Unicode 可读主题加稳定哈希；`AI`、`AI前端` 和纯中文主题不再落到同一个 `ai-plan.md` 或 `learning-topic-plan.md`。
- Plan、课程树和学习状态改为带回滚备份的事务提交；任一文件替换失败会恢复旧版本，回滚失败时保留唯一恢复目录。
- 课件生成改为先在内存完成结构校验，再次核对项目 revision、主题和当前知识点后才落盘；项目已切换时前端自动读取当前课程，不再显示笼统的 `Failed to fetch`。
- Plan 只有处于“等待确认”且没有活动生成任务时才能确认；草稿或尚在生成中的计划不能越过门禁直接开始课件。
- 修复行内代码中的 `===` 被再次误解析为 `==高亮==` 的问题；代码已有底色时不再嵌套第二层黄色高亮。
- 修复课程已生成却因面试题数组字段被模型返回为字符串而整份失败的问题；常见格式偏差现在本地瞬时归一化，不再重新调用模型生成整章。
- macOS 后台启动改为统一走 `run.sh`；如果缺少教学快照会先自动准备，避免出现“页面已连接、课程却不可用”。
- 用户学习记忆不再只留在前端：新增 `profile.json`、可恢复的 `intent-state.json`、追加式 `intent-events.jsonl` 与 `conversation-events.jsonl`。
- 学习项目快照现在完整覆盖个人画像、onboarding、题库、面试库和真实 `projects/` 练习目录，避免切换课程时状态混用。
- 面试 onboarding 新增目标岗位、技术栈、真实题来源和已入库题数槽位；依次补齐后才生成 Plan。有题先粘贴入库，无题按岗位与技术栈研究。
- 右侧要求“再出几道题”改由 Codex harness 读取出题 Skills；验证成功后追加到当前 HTML PPT 总结页之前并同步题库，失败时保留旧讲义。
- 追加题的答案解析只保存在私人题库，不再通过公开讲义字段提前泄题；题库写入失败时会自动恢复原讲义。
- 学习项目恢复改为完整暂存后再切换，复制中断时不会清除当前课程。
- Onboarding 改为“证据优先”的意图判断：用户明确说出“初学 / 有基础 / 熟练”时直接填入水平槽位，不再重复追问；只有真正缺少水平证据时才显示 3 个紧凑选项。
- Fast 模型连续输出坏结构时，明确的“岗位面试 + 岗位 + 基础”请求会启用窄范围槽位恢复；它只复用用户原话，不猜知识水平，也不会把普通学习请求强行路由成面试。
- 水平证据现在必须能追溯到用户当前输入、历史原话或已确认槽位；只回答水平时，模型不能擅自替换已经确认的主题和学习结果。
- 网络、鉴权或超时故障不再连续调用模型三次；只有 JSON/语义校验错误才进入有限修复。
- 面试诊断禁止退化为 Go/Python 通用语法题，每一道岗位题都必须带有目标岗位或领域锚点。
- 课程二次模型修复会重新携带主题、路线、章节与知识点范围；修复后的叙述若没有覆盖当前知识点会被拒绝保存。
- 诊断题只在输入框上方的选择区显示一次，不再同时重复成聊天气泡。
- “RAG 是什么意思”一类定义型请求直接进入概念理解路线，不再套用项目、面试或长期学习问题。
- 面试岗位使用岗位专属诊断题，并校验模型返回的主题必须与用户目标一致；未知岗位生成失败时明确重试，不再降级成无关的通用技术题。
- 选择题上方会显示当前诊断问题，避免只看到答案、不知道正在回答什么。
- 课程 JSON 增加二次模型修复：当选择题漏答案、答案不属于选项或课后作业结构不完整时，携带具体校验错误让模型完整重写，再次校验后才保存。
- 修复符号链接用户目录下 `plan.md` 被错误判定为越界路径的问题。
- 增加六类真实学习场景的端到端冒烟工具，覆盖意图、追问、诊断、Plan、确认和第一份 HTML PPT。
- 浏览器实点验证“我要面试前端岗”会先询问真实水平，不再出现 DOM 事件流等无关诊断题。
- 生成进度卡片分离“整体说明”与“当前步骤”，不再显示两行同步重复文字。
- 移除未提供稳定转写服务的语音按钮、浏览器识别脚本与相关样式，输入区仅保留文本与发送。
- 对“面试 + 岗位/主题 + 起点”的明确输入直接生成面试 Plan，不再追问通用概念、语法或项目路线。
- 研究产物可兼容展示性的岗位和路线修饰，但会将主题归一为用户原始目标；真实的跨主题资料仍会被拒绝。
- README 补充 workspace `publish` 说明：它是已验证 Skills 和知识库的本地运行快照，不是网络上传或包发布。
