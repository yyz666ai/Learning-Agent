# 本地状态事务契约

## 事实源与启动预算

学习状态写入根目录是环境变量 `USER_DIR` 指向的用户目录（`userdir/u_<user_id>/`），`tools/workspace_utils.py` 的 `state_root()` 负责解析（读不到 `USER_DIR` 时回退到 manifest 的 `state_root` / 本地 `user-data/`，供脱离桥的本地开发用）。模板整体只读、可版本化升级，用户状态独立存放、不受模板升级影响。启动时只读取状态根目录下的 `profile.md`、`learning-state.json`，以及当前请求引用的活动计划、掌握节点、复习摘要和项目链接；不得扫描全部历史。

## 写入顺序

1. 解析当前 JSON 并校验对应 Schema。
2. 比较调用方提供的 `revision`。
3. 生成新状态，禁止调用方自行修改 `revision`。
4. 在目标文件同目录写入临时文件并重新解析。
5. 原子替换目标文件并读回确认。
6. 成功后向当月 `history/learning-events-YYYY-MM.jsonl` 追加证据事件。

## 禁止行为

- 写入状态根目录之外的业务状态。
- 覆盖无法解析的原文件。
- 删除历史证据来让当前状态看起来一致。
- 未读回成功就声称保存完成。

## 失败行为

Schema、revision、原子替换、读回或事件追加任一步失败时，报告具体失败并停止。能安全回滚时恢复原状态；不能确认一致性时切换为只读。
