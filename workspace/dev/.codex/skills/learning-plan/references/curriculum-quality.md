# 课程章节质量与时间契约

用于生成和修订 Plan。按用户真正的目标选择内容，不是所有路线统一套章节。

## 成功证据先于章节清单

每项承诺的能力必须能指到先修、具体章节、实际练习与完成证据。知识地图列了却没有教学的内容，标“选修/后续拓展”或删除承诺。毕业要求中的必选/可选保持一致。

先修可以提前教或在当前课显式铺桥；不能因为用户会 HTTP 就推断他会 channel/select。强项有证据可复用，不重新摸底。合成测试画像只能称给定输入，不声称用户实际做过题。

每课先确定能完成的动作，再决定知识量。口述概念不能替代独立编程；对 hands_on 学习者，每个适合编程的单元提供一个小型编写/修改/排错任务，先尝试再选择提示。允许浏览后续内容不代表掌握前置能力。

## 统一预算和执行顺序

每阶段写预计课次（整章总数）、单次分钟、课外练习分钟；例：预计课次 2、单次分钟 40、课外练习分钟 30，表示课堂合计约 80 分钟，课外另约 30 分钟，不是每个知识点各 2 次课。估计不是保证；未知输入不能编成实测值。

单章需要多课时，在计划中列每次的目标与暂停点，不把一份整章讲义称为一节课能全部完成。安装/网络故障时间单列余量。面试模拟 30 分钟＋复盘 10 分钟可是一课；40 分钟模拟再复盘不能仍称总计40分钟。

当前课程导航按线性顺序推进。Mermaid 只显示与实际章节一致的线性路径；不要声明不存在的并行解锁或用图替代真实 prerequisites。

## 按场景核查

### 初学编程（Go 的易错桥梁）

- 环境第一步先核对系统、安装/编辑器、版本和目录；先版本验证，文件建立后再运行。版本标准在 Plan 和课件一致。
- 结构体可以先介绍；地址/解引用、值复制和指针参数必须早于“何时选指针接收者”的决策验收。
- 函数课安排正常/错误路径的独立小函数；接口课安排替换实现并运行行为，不只解释关键词。
- 早期引入格式化、读编译错误和输入—期望自检。给微型程序逐步加功能，不等到很后面才第一次独立编码。
- CLI 跨进程保留状态须明确文件/数据库保存；内存版必须说明退出会丢，不让用户误以为跨命令持久化已完成。
- SQL/SQLite 前补表、键、CRUD、驱动/连接和最小建表，再讲事务/回滚。并发共享修改必须有互斥/原子/所有权之一的正确练习。
- 泛型、PGO、TLS 只在目标需要时加入，有对应学习与验收；否则明确选修。不要为“完整”堆名词。

### 精进与项目

明确任务生命周期：请求内工作还是响应后继续的异步任务；两者的 Context 和收尾责任不同。缺并发先修可在案例旁给小桥梁，之后让用户独立迁移。

背压应包含有界并发/队列、等待或拒绝策略及过载测试；如果仅讲超时，把标题准确写成超时传播。泄漏以本任务 done/资源归还与有界退出为主证据，进程 goroutine 总数仅辅助。优雅关停要说明期限与到期策略，不承诺任意卡死任务永不丢失。

### 面试

目标岗位、级别、技术栈、期限和真题状态分别保留“已知/未确认/明确没有”。用户有资料可直接粘贴，不以选择题增加步骤。岗位未知只能做通用准备；收到岗位后允许调整任意未完成阶段，保留已完成证据。

先教写程序再叠加表达。猜数字若要求交互，要教输入、转换、重试/终止；未教就选固定列表任务。字典/集合操作与可变性/复制可拆课，对象基础与继承/魔术方法也不能挤成一次口述。

模拟评分至少包含事实正确、独立编码/边界、解释追问三维；提供行为锚点，例如0=核心错误/不能完成，1=提示后完成但仍有缺漏，2=独立完成常见情形并能解释，3=独立覆盖边界并应对变体。通过条件由岗位目标确定并明写；核心事实或代码错误不能靠表达流利抵消。题目注明用户真题、公开来源或合成练习，不冒充真实招聘题。

### 本科、临考、阅读代码与单概念

本科按已修课程、数学基础与学期目标排依赖，不把一门语言工程课称为完整专业。临考按日期、考试范围、题型与错题优先级做减法，不强塞毕业工程项目。阅读现有项目按运行条件、入口、数据流、目标模块与小修改验证组织。单概念只需短解释、场景判断和可选代码，不为了阶段数扩成系统课程。

需求期限不可达时明确短期可达目标与后续路线，不保证零基础三天达到高级岗位。以上是质量约束，不是固定章节模板；输出前逐项核对实际用户所需部分。
