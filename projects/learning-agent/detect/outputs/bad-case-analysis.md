# Bad Case 与修复记录

本文件只说明本轮观察，不覆盖第一次失败，也不把用户提供的 Windows 外部日志当成本轮实测。

## BC-01：同步诊断穿过短超时代理

原实现 `/api/onboarding/start` 在模型返回前不结束HTTP请求。受控阻塞探针证明同步等待；外部WorkBuddy具体断开阈值未独立验证。现在网页使用202启动+短轮询，35秒受控测试中启动约0.011秒返回，模型只执行一次。旧同步兼容端点保留，不承诺它能避开代理超时。

## BC-02：Windows启动边界与进程树

原run.sh只查bin/python，Codex入口分散、长中文prompt通过命令行参数。统一Python启动流程、Windows run.cmd、npm shim解析与UTF-8 stdin。审查还发现只终止Node包装器可能遗留实际Codex子进程；补充真实POSIX父/孙进程测试与Windows精确PID树终止模拟。原生Windows仍需要现场验收。

## BC-03：看似成功的系统操作

打开目录HTTP200不一定代表系统文件管理器成功；提醒配置保存也不等于Windows能发送通知。现在返回真实opened/capability/message，前端不再显示虚假成功。没有GUI时给手动路径。

## BC-04：取消后恢复和确认重试

本轮新代码审查实际复现了取消后复用旧request_id导致无法重试，以及第一次确认200、同请求再确认409。修复后取消必须恢复权威intent再建新ID；相同确认重放持久收据；仅精确匹配原生成取消状态才允许续建。不同项目、不同目标、不同提交继续拒绝。晚到的确认和Plan响应增加epoch保护，不修改新会话UI。

## BC-05：评测调用器仍使用旧合同

第一次全量回归673通过、1失败：e2e测试夹具缺少新接口需要的intent session/revision，且期待旧同步endpoint。这是评测夹具未随新API更新；修复为断言202协议所需字段和8秒请求上限，没有放宽产品校验。

## BC-06：报告数据与交互边界

审查补查空白证据、非有限JSON数值、错误limitations类型、原型敏感case_id和保存后焦点回归。自动测试覆盖安全转义、保留首次失败、筛选/详情/草稿/导出；真实浏览器打开报告被工具安全策略拒绝，未绕过，视觉验收保留BLOCKED。

## BC-07：真实小白Plan格式校验

2026-08-30的一次真实Go初学画像测试，模型262.03秒返回完整草案，但被结构校验拒绝。已定位到知识点标题被模型写成 `- #### 知识点`，其下列表缩进两个空格；校验器只认顶格 `#### 知识点` 与顶格列表。它不是“没有返回内容”，也不是这次诊断接口的代理超时。对应修复/回放/后续课件结果以报告最新run为准，不用“单测全绿”掩盖这次真实失败。

## 尚未覆盖的风险

原生Windows、实际代理断连、磁盘写入中途故障、不同模型与大量画像的教学质量。尤其确认后、收据落盘前磁盘故障不具备完整跨文件事务恢复保证。当前后台调度仅支持单服务进程。上述风险不能用本轮通过数量消除。
