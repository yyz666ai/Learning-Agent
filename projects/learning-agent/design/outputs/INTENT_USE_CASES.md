## 1. 本次决定与交付边界

**目的：用户说出学习需求后，系统能问对下一句话，并在信息足够时停止追问。** 不是把用户变成必须填完所有槽位的表单。

- 已知：用户要求动态选项、无默认选择、资料问题开放回答、完整保留问题和答案；最近一次真实测试发现多类误判。
- 已知：目前同时存在 Skill 指令、Python 语义校验和前端本地分支，三者都可能改变实际行为。
- 已实施：模型理解语义 + Python 管理证据与状态 + 前端呈现交互。具体实测及剩余边界见第10节和独立评测报告。
- 尚未完成验收：考试新路线的真实 Plan/PPT、全部42种主用例与4种子例的完整端到端覆盖。
- 无需用户决定：整理证据、编写用例、独立评审、修订建议回复。
- 已确认：用户“请开始吧”授权混合修复方案，已修改 Skill、Python 和前端，不新建分支。
- 第2–9节保留最初基线和设计过程，其中“建议回复”仍是目标示例，不冒充真实生成；新增真实结果独立记录，不覆盖失败证据。

### 方案比较

| 方案 | 得到什么 | 局限 |
|---|---|---|
| 只改 Skill | 较快改善措辞、提问策略 | 无法消除 Python 错误校验、刷新丢证据和前端误入库 |
| **混合方案（推荐）** | 模型负责理解，代码保证记录与合同，界面提供快捷输入 | 需要联动回归测试，不能只看一份提示词 |
| 全部固定问卷 | 容易做确定性测试 | 重复提问、组合需求难处理，不符合本产品目标 |

## 2. 证据口径：什么是“当前回复”

基线代码 `800fdaf`；真实测试于 2026-08-30 执行，20 组场景、45 次意图请求、61 次真实 DeepSeek 调用。调用了真实 Python 意图处理函数、模型与校验，隔离用户目录；没有执行 Plan/PPT 生成，也不是完整浏览器验收。

上一轮报告：[REPORT.md](../../../../evals/runs/2026-08-30-intent-audit/REPORT.md)。原始数据：[results.json](../../../../evals/runs/2026-08-30-intent-audit/results.json)、[recheck.json](../../../../evals/runs/2026-08-30-intent-audit/recheck.json)、[前端路由探针](../../../../evals/runs/2026-08-30-intent-audit/frontend-probe.json)。这些原始运行文件被 Git 忽略，克隆仓库未必包含；下文保留了可阅读的关键原话和结论。

严格区分四层：

1. `raw_model`：模型第一次返回的 JSON，可能正确但被校验器拒绝。
2. `final_decision`：服务端修复/校验后的最终 action、slots、question。
3. `visible_reply`：浏览器真正显示的题干、选项、提示。不能把内部 `summary` 假装成气泡原话。
4. `side_effect`：是否入库、是否创建计划、是否保留历史和项目。没有执行就写“未测”。

以下当前题干引用 `final_decision.question.prompt`；无题干的项列结构化结果，不冒充用户可见文字。后续应保存四层证据和同一 request_id，才能区分模型、校验、界面故障。

代码核对补充：当前 `showChoices()` 没有发现自动预选，因此“无预选”属于必须保留的回归要求，不是已证实的现有缺陷。`beginDiagnosis()` 已有诊断前提示，`renderDiagnostic()` 已将题干加入聊天；仍需验收完整历史恢复，不能把这两项描述成尚未实现。

## 3. 全局体验合同

### 3.1 什么情况下才问

模型每轮先理解用户当前原话、同一学习项目历史和已确认事实，再决定动作。只有缺失信息会实质改变学习范围、起点、材料或期限安排时才问。

- 一次一个主要问题。可接受用户一次回答多个槽位，下一轮自动跳过已填信息。
- 不把“初学 / 精进 / 面试”当所有人的固定入口：这是部分模糊输入的候选，不是全局菜单。
- 已明确的目标不再换同义词确认，例如“独立做项目”不再问“是不是想完成项目”。
- 一次性概念问题、当前课程答疑不强迫提供完整画像。
- 不知道、暂时没有、先按通用方案，都可以形成明确的未知/无资料状态；不得无限追问。
- 有基础诊断前，先说明目的：“你提到已有基础，我会用几道短题找出需要补的部分；题目和你的回答都会保留。”初学者不突然收到技术测试。
- Plan 草稿仍需用户确认；“信息足够”不等于直接开始整套课程。

### 3.2 动态选项与直接输入行

普通意图澄清可提供 2–3 个语义不同、与当前输入相关的快捷回答；没有合理选项时直接开放提问，不能为满足数量凑选项。

例如用户想精进 Java 并发，但未说具体困惑：

> 你这次更想解决哪一部分？
>
> A. 线程安全与共享状态　ⓘ
> B. 线程池与任务调度　ⓘ
> C. 结合现有项目排查问题　ⓘ
> 补充你的实际需求：[可直接输入文本　　　　　　　　　发送]

最后一行是**输入控件，不是一个必须先选择的 D 答案**。直接输入、Enter 发送；不先点击“其他”。这里展示的是形态示例，不能作为所有并发需求的固定选项列表。

验收：

1. 初始无 selected/checked 答案；自动聚焦输入框不等于选择答案。
2. 点击某个快捷项才提交该项含义；未点击、空输入、刷新、按 Tab 都不提交默认值。
3. 输入行和主输入框走同一语义处理入口，保留完整原文；不得映射到最近的预设项。
4. 中文输入法合成中的 Enter 不发送；普通 Enter 发送，Shift+Enter 换行；空白不发；等待期间防止重复提交。
5. 悬浮或键盘聚焦 ⓘ 查看详情，不提交选项；触屏可打开详情。
6. 选择后选项控件可消失，但 Agent 原问题和用户答案都留在历史，刷新后可恢复。
7. 新问题不继承上一题选择状态；过期控件不能提交到新 question_id。
8. 资料收集题完全不出 A/B/C，也不出“有/没有”：直接粘贴或回复没有即可。
9. 以上是**意图澄清控件**规则，不把自由文本答案偷偷记成课堂单选题的正确/错误。

## 5. Use Case 合同与可追溯结构

所有用例共用：参与者为学习者、意图模型、Python Harness、前端；触发是用户明确发送消息/选择；输入含本轮原文、同项目历史、可信状态、当前页面上下文。主路径：读证据 → 更新槽位 → 判断缺口 → 追问或路由 → 校验 → 持久化 → 展示。异常必须保留原文，不能静默猜选项。

后置条件：记录用户原话、问题、选项版本、决定和证据；不凭意图结果伪造题库入库/掌握度；进入 Plan 是生成待确认草稿，不越过用户确认。责任：模型建议语义，Python验证事实与状态，前端展示，不得自行以字符串兜底改用户目标。

追溯：J1自由表达 → F1澄清 → F2就绪 → F3确认；J2当前学习 → F4上下文操作。故事 S1少回答重复问题、S2保留需求、S3顺畅提交资料、S4不中断学习、S5可恢复。下列 UC 关联 Q 与验收规则，评测记录引用同一 UC ID。

## 6. 评测智能体：可复用角色与评审机制

本轮已启动独立评测智能体，读取基线证据与本文进行只读评审。它不是生产教师代理，不替学习者选答案，不可修改生产用户文件。可复用的评审指令见 [INTENT_EVALUATOR.md](INTENT_EVALUATOR.md)。当前是人工触发的独立代理，**尚未集成为自动执行器或CI**。

### 评分（建议阈值，待采纳）

每个维度0–2分：0错误/遗漏，1部分满足，2满足且有证据。总分12。

| 维度 | 判定重点 |
|---|---|
| D1 意图与范围 | 路线适合用户目标，代码需求/否定/多个目标不丢 |
| D2 追问必要性 | 仅补会影响方案的缺口，不问已答问题 |
| D3 证据与记忆 | 不伪造能力，刷新/纠正后事实一致，分项目取证 |
| D4 交互适配 | 动态无默认；资料开放；自由输入不被挤成选项 |
| D5 动作与副作用 | 路由正确，真实入库后才更新计数，无越权或重复操作 |
| D6 表达与恢复 | 题干清楚、先说明诊断、历史保留、错误可恢复 |

建议六维都适用且证据齐全时，单例通过需≥10/12且无任何维度0分、无硬否决。区分：`not_applicable` 是本用例不涉及的能力；`not_evaluated` 是应检查却缺证据。前者由用例预先指定而非评审员事后删分，分母扣除该维2分；分数要求至少达到适用总分的5/6，且适用维度无0分。

存在任一适用维度 `not_evaluated` 时，整体不能pass：已有硬失败则fail，否则整体not_evaluated；可以另外报告“语义层通过、界面未测”。例如仅API测试无法证明无预选或输入控件可用，不能用其余五维10分冒充全链路通过。

硬否决：伪造用户能力/资料/题数；丢失明确否定或实现要求；把当前答疑变成新建课程；未经操作默认提交；把无资料话语入库；跨项目污染；关键原始模型正确却被代码反向改错。

发布前建议：所有本次已知失败种子修复后每例独立运行3次；每条主要路线补至少2个未参与修复的改写输入。关键硬否决0例。分别统计用例通过率、请求通过率、首次成功率、平均调用次数、重复追问率、延迟P50/P95及样本数，不能用61次模型调用当61个独立用户案例。

| 字段 | 内容 |
|---|---|
| case_id / variant / run_id | UC号、改写编号、本轮唯一ID |

### 迭代与停止

冻结基线 → 独立评价 → 优先改反复出现的根因 → 针对旧失败写回归 → 改Skill/代码 → 真实复测 → 留出改写测试 → 再评。

每轮最多三次模型格式修复，产品改动评测建议最多三轮后人审；持续失败保留为阻塞项，不靠无限循环、改低阈值或删失败用例宣布通过。最终上线决定归用户，评测智能体只建议。

### 复现方法

在项目根目录执行：

```sh
.venv/bin/python -m pytest -q
node --test tests/onboarding_interaction.test.cjs
.venv/bin/python tools/evaluate_intent.py --output evals/runs/my-intent-check --repeat 2
.venv/bin/python tools/serve_intent_eval.py
```

最后一条打开隔离测试服务 `http://127.0.0.1:8789/?user_id=eval_local`，只允许意图POST，不执行真实课程生成。真实模型评测使用项目DeepSeek配置，会消耗API额度；用户文件写入临时目录，停止后移除测试数据。`evals/runs/`被Git忽略，公开的是脱敏评审结果与测试脚本，原始真实用户资料不得公开。

### 当前仍需分清的边界

1. 已改工作区代码，不等于正在运行的旧后台已自动更新。重新运行项目已有 `bash run.sh` 会自检并同步工作区Skill发布快照，再加载新Python；不修改全局Codex设置。
2. 不承诺所有自然语言永不出错；模型可能需要修复调用，服务也可能不可达。失败时不得假装已经生成Plan或偷偷选一个答案。
3. 当前历史上下文保留最近40条供模型与校验共同使用，JSONL仍保留事件；没有实现无限历史、逐槽位确认状态或完整事实来源图。
4. 幂等缓存是最近请求，锁为单进程项目级；多worker/多机器部署需要数据库事务/跨进程锁，不能用本轮测试证明分布式一致性。
5. 新本科/考试路线已通过状态Schema和规划提示衔接测试，但未执行真实“Plan确认→HTML PPT→做题→课后复习”全链路。下一轮应按UC04-a/b、UC28/29、UC36/40继续独立验收。
