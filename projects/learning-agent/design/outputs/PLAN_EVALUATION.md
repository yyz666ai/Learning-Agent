## 2. 主代理已复核的结构问题

### B-01：指针接收者先于指针基础

原文 B 133–146 行：阶段 7 已要求选择值/指针接收者，并验收“为什么该用指针接收者”；阶段 8 才介绍指针与内存。

判断：前置依赖不通过。应先介绍地址、解引用、值复制和指针参数，再进入方法接收者。不是把所有方法都推迟，只需区分值接收者初识与指针接收者决策。

### B-02：知识地图没有全部落到教学任务

原文 B 34、40、41 行列出泛型、PGO、TLS；仅在地图中声明不足以证明有讲解、实践与验收。完整工程师路线应建立“承诺能力 → 章节 → 练习 → 验收”的对应；高级内容可标选修，不应通过堆入地图制造“全覆盖”。

### B-03：数据库先修缺口

原文 B 247–254 行直接进入 database/sql、SQLite、事务和参数化查询。零基础需要先知道表、键、CRUD 和最小 SQL，再理解 Go 驱动接口与事务边界。可以新增短先修单元，也可以明确本阶段包含这些前置内容，不能默认会 SQL。

### A-01：首课依赖尚未建立的并发概念

阶段 1 从熟悉的 HTTP 场景切入是优点，但马上要求实现取消并用竞态检测验证；channel、多路等待、Context 的系统说明在后续阶段。应把首课限定为运行和观察最小失败样例，先铺垫本课必需的 done/select/任务所有权；不要把 HTTP 基础好推断为并发基础好。

### A-02：标题承诺背压，内容只讲超时

阶段 6 标题“超时与背压”，正文、练习、完成证据主要覆盖超时。背压需有有界队列/并发限额、过载时等待或拒绝、取消与额度释放等可观察行为。应补真实背压单元，或准确更名并明确背压不属于本轮。

### A-03：泄漏证据不能只靠全进程 goroutine 数量

阶段 2 和 8 需要任务自己的退出信号、资源计数、超时断言与 race 结果；goroutine 总数仅作辅助。该问题已在上一轮课件审查中暴露，不应只修 PPT 而保留有歧义的大纲验收。

### I-01：缺岗位不能承诺岗位面试达标

原文 I 8 行明确“岗位暂未确认”，却在 43–47、146–150 行以“目标岗位模拟面试”为最终目标。诚实的草案应称为 Python 通用基础与面试表达准备；用户补充岗位、技术栈和时间后，才能确定岗位范围与终局标准。不能凭 Python 语言自动推断后端、数据或 AI 工程岗。

### I-02：学习资料来源尚未完成确认

画像写着“面试题来源尚未确认”。当前样本不能证明“用户回答没有真题 → 系统查证公开资料 → 依岗位出题”全链路已经合理。正式针对性规划前应直接问用户有没有题目/JD，有则直接粘贴，无则明确按通用材料准备，不能伪造来源。

### X-01：Plan 课次与结构化课程的口径不同

`backend/curriculum.py:105–108` 只识别 `- 预计课次：N`；不识别进阶 Plan 里的引用行“约 1 次课（40 分钟）”。随后把阶段课次向上取整到每个知识点且至少为 1。

例：进阶首阶段 4 个知识点各写 1 次课，而 Plan 约 1 次课；面试首阶段 5 个知识点各 1 次课，而当前任务约 40 分钟。首课生成又会合并整章知识点。

这不是已测出真实学习耗时，而是数据语义不一致。建议阶段保存总课次和单次分钟，知识点保存预计分钟/单元分配，不用每点至少一整课的取整规则重复计算。渲染 Plan、大纲及课件范围都应读取同一结构化课时来源。

### X-02：依赖图与实际导航没有同一来源

`curriculum_from_plan` 为每个知识点默认连接前一个点。Plan Mermaid 中的并行、汇合依赖并未变成真实课程依赖。应明确首期严格线性排课并让图与顺序一致，或实现结构化 prerequisites；不能展示一张看似灵活的图却让后台执行另一套规则。

### X-03：结构校验不是教学质量校验

`normalize_and_validate_plan` 检查标题、阶段数量、练习和证据字段、完整路线的覆盖地图等，但不会证明先修正确、时长合理、岗位对齐或标题承诺得到实际教学。建议另加语义评判与明确失败原因，不把所有内容问题都报成“权威资料结构失败”。

## 6. 独立评判补充：逐类课程如何改

### 6.1 零基础 Go

优点：环境起步、CLI/HTTP/持久化/测试等工程路径清晰，每章有练习和完成证据，不只是语言语法目录。

进一步问题与证据：

- **项目出现较晚且状态边界不明确**：第 14 阶段才交付任务清单 CLI（B 193–200 行），要跨命令增删查，正式数据库持久化却到阶段 20。第 10 阶段文件练习可以铺桥，但需明确 CLI v1 使用 JSON 文件还是单次进程内交互。
- **并发共享状态缺少解决任务**：阶段 15 要发现共享修改风险，毕业要求并发提醒且 race 无报告；必须教保护共享状态或避免共享的策略，并给实际练习。
- **工具可以早用、晚系统讲**：测试在阶段 12、调试在 13、格式化在 24。建议第一份程序就会格式化和读报错；函数阶段加入输入—期望自检，后面再系统深化，不必都拖到后半段。
- **毕业标准相互矛盾**：B 12、47 行要求 HTTP API，56 行又写“可选 HTTP API”，306 行再写必交。统一基础达标与拓展达标。
- **解释题不能替代编程验收**：函数阶段用解释“为什么不用异常”作主要证据（118 行）；接口阶段强调不需要 implements（154 行）。应同时验收能独立实现函数正常/错误路径、替换接口实现并保持行为。
- **课外作业和浏览权限分开**：可以允许跳到下一章浏览，但环境尚未跑通、练习没交不能自动标记实际能力掌握。

建议顺序（是修订提案，未覆盖原文件）：

1. 环境、目录、首个程序；安装异常允许单独延长。
2. 输入—处理—输出、变量、运算与简单调试。
3. 分支、循环和微型统计工具。
4. 函数、多返回值、最小错误处理、输入—期望测试。
5. 切片、map、字符串；交付词频工具。
6. 结构体建模。
7. 指针、值传递、共享修改。
8. 方法、接收者与接口，用可替换存储实践。
9. 文件、defer、错误传播；JSON 持久化。
10. 模块、包、测试、调试整合；CLI v1。
11. goroutine 生命周期、等待与共享状态保护。
12. channel/select、取消、超时；并发小任务。
13. HTTP/JSON/handler 测试。
14. 表、键、SQL CRUD、SQLite 接入，再学事务与存储迁移。
15. race、fuzz、基准、profile、安全及发布，按实际预算拆单课。
16. 集成项目、陌生任务迁移与复盘；泛型、PGO、TLS 明确选修或给出独立验收。

需要补问：操作系统/编辑器可用状态、每周可安排课次、工程目标更偏 CLI 还是后端。不要重复问已确认的零基础。

### 6.2 进阶 Go

优点：强项只复用，围绕取消与泄漏补缺口，最后迁移到非 HTTP 情境，个性化是可见的。

进一步问题与证据：

- **关停承诺过于绝对**：A 8、85–87 行写“不丢在途请求”，没有限定关停期限、永不完成请求如何处理、后台任务是否在等待集合。改成正常收尾与期限到达后的取消/保存/告警两类验收。
- **“提交任务”与请求内工作需要选定**：A 99 行的后台执行与断连取消容易混淆异步任务服务和请求内任务。先明确任务生命周期，才能决定哪个 Context 应拥有它。
- **40 分钟不能隐藏课外工作**：A 113 行给讲解 15 分钟、动手 20 分钟、收尾 5 分钟；实际空白文件实现服务与测试被留作课后。必须另写课外预算，不把它假装包含在课堂时间中。
- **合成证据不能包装真实诊断**：A learning-state 29–32 行明确为 evaluation fixture；Plan 15、122 行却写“4 道题正确率 80%”“题目覆盖显示”。应表述“已确认的测试画像指出……”。本样本不证明真实用户做过这些题，更不证明诊断准确。

建议顺序：

1. 熟悉 handler 的失败场景，明确任务应活多久，做最小运行预测。
2. 生命周期与退出证据：创建者、done、有界等待、泄漏线索。
3. channel/select 阻塞、关闭与可取消等待。
4. Context 传递、派生、cancel 和资源释放。
5. 回到请求取消，独立完成正常／取消双路径修复。
6. 文件、响应体等资源所有权与 defer 异常路径。
7. 超时传播。
8. 有界并发与背压（不教则删除标题承诺）。
9. 关停、后台任务收尾与期限策略。
10. 综合 HTTP 服务验收，再做非 HTTP 陌生迁移。

竞态和转储按需作为证据工具逐步出现；已掌握的 HTTP 和表驱动测试不重讲。补问请求内任务还是长期异步任务、有无脱敏故障代码及每周节奏。

### 6.3 零基础 Python 面试

优点：没有假装已经拿到真题，承认岗位未知，并且先补环境和基础。这适合作为通用预备课，而非已定稿的岗位冲刺路线。

进一步问题与证据：

- **能力域不一致**：I 14 行第六域为“表达与追问”，106 行变成“工程与场景”；后续没有工程场景落点。应统一能力图，岗位专项作为待确认分支。
- **综合题需要匹配已经教的先修**：I 100 行可选猜数字，但没有明确输入读取、转换失败、循环终止。可先选固定列表计分；如果选交互猜数字，就补必需知识。
- **部分章节过密**：阶段 10 同时有字典、集合、可变性、哈希、深浅复制；阶段 13 同时有类、self、属性、魔术方法、继承。按单课可验证目标拆解，不等于每个名词都另建一章。
- **动手优先落地不足**：阶段 2、4、6 主要口述与预测，首个综合编码到阶段 7。每课加短小独立编码／修复，再练一分钟解释，避免只学会回答模板。
- **评分标准未定义**：I 114 行要求“3 档以上”，149–150 行按 rubric 判最终达标，却没有档位总数、行为锚点和必过项。至少分别评价事实正确、独立编码与边界、解释追问；事实和代码错误不能用表达流利抵消。
- **环境验收漂移**：Plan 60 行要求 Python ≥3.10，首课只把输出以 Python 3. 开头当成功，不能证明满足版本要求。课程环境提示必须与 Plan 同源。
- **新岗位不能只调整第 8 阶段之后**：Plan 8、160 行预先限制调整区间。应保留已完成证据，但允许重新安排任何尚未完成的先修与专项。

建议顺序：

1. 环境与首个脚本。
2. 变量、表达式、字符串，独立改脚本。
3. 条件、循环、基本输入，做非模板小题。
4. 函数、返回值和参数。
5. list/dict/set/tuple 操作与选型。
6. 引用、可变性、复制，分别推演与编码。
7. 最小综合程序和基本错误处理，验证先修是否真正可用。
8. 岗位信息若仍缺失，在进入专项前确认岗位/层级/栈/题源/时间，产出岗位能力图；用户提前提供则提前调整。
9. 作用域和默认参数等陷阱。
10. 对象基础、类/实例属性；魔术方法、继承按需求拆课。
11. 岗位专项与真题变体，区分真实来源与合成练习。
12. 回答结构融入日常练习，专项错题复测。
13. 限时独立编码、简答与追问模拟，使用明确评分锚点；复盘另计时间。

优先补问岗位/JD和级别、面试日期与每周投入、真题材料、目标栈；已确认零基础不重问。

## 7. 结论

三份大纲不是完全同一套模板，已经体现了初学、精进、面试的方向差异；但是教学依赖、时间预算、能力承诺与实际验收还没形成统一闭环。应该修的是“目标—先修—章节—课次—练习—证据”的映射，而不是只增加章节数量。

三个样本的状态文件均已确认 Plan，但 Markdown 末尾仍写草案。显示应以当前状态为准，不应误判为用户尚未确认；反过来，状态 confirmed/completed 也不能推导课程质量通过。
