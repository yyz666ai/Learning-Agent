# 课件编辑、确认与撤销设计

日期：2026-08-30。状态：**方案已获用户批准，核心实现及最终自动化回归已完成；浏览器已验证编辑、候选应用和撤销，其他未认证范围见发布报告**。

本文保留批准时的目标合同，不将每条验收要求都自动视为已通过。最新证据和待补项见 [发布验证报告](SAFE_EDITING_RELEASE_VALIDATION.md)；任务状态见 [实施计划](SAFE_EDITING_IMPLEMENTATION_PLAN.md)。

实际实现已经包含只读／编辑、七种格式、Markdown 预览与导出、提议双确认、题目配对答案校验、版本恢复和代码／作答历史保留。存储采用 `lessons/.versions/<knowledge-point-id>/current.json`、同目录 `<revision>.json` 配对快照与 `<revision>/lesson.md`；提议在 `lessons/.proposals/`，本地草稿在浏览器中。候选直接通过显式只读 Codex 调用返回 JSON，无需模型写暂存文件。当前仅按单服务进程提供互斥保证。

## 1. 推荐结论

保留分页课堂，正文用 Markdown 编辑，选择题、答案键、作答和进度仍使用结构化数据。后台同时保存可读 Markdown 和可恢复版本。HTML 是呈现方式，不是唯一内容来源。

不建议把课件变成任意 HTML 编辑器，也不建议为了 Markdown 放弃点击题。Markdown 本身只描述文档，点击答题、判分、持久化仍由网页组件与后端负责。两者并不冲突。

### 可选路线

| 路线 | 收益 | 代价 | 建议 |
| --- | --- | --- | --- |
| 分页课件＋Markdown 编辑预览＋结构化题目 | 延续当前课堂；文档易保存；变更可审计；普通编辑不花模型 token | 编辑时会看到少量 Markdown 标记 | **首期采用** |
| 完全笔记式长文＋嵌入题目组件 | 连续阅读方便，仍可保留点击题 | 要重做分页、完成条件、选区与进度定位 | 后续可增加阅读视图，不重写内容格式 |
| 所见即所得富文本编辑器 | 像常见笔记软件直接编辑 | 富文本与 Markdown 双向转换、粘贴、代码、公式和撤销更复杂 | 不与首期安全修订一起扩大范围 |

## 2. 实施前核查（历史基线）

以下描述是批准方案前的旧实现问题，用于解释设计动机，不是当前功能清单。旧 `/remediate` 直写、无历史快照和缺少下划线等问题已在本次实现中处理。

- `backend/lesson_manifest.py`：每页已有 title、markdown、code、question、options；不是模型输出整份独立 HTML 后任意执行。
- `frontend/js/markdown.js`：正文支持标题、加粗、斜体、高亮、代码和 Mermaid；目前没有下划线支持；部分组合标记需要完善测试。
- `frontend/js/app.js:reviseCurrentLesson`：识别到修改表达后直接调用 `/api/lesson/remediate`，没有执行前确认。
- `backend/main.py:remediate_lesson`：转入强制生成；当前是整章生成后保存，并非真正限定受影响页面的草案应用。
- `backend/lesson_generator.py:save_lesson_bundle`：替换当前 JSON 和答案文件；临时文件重命名不等于保留历史版本，也不构成多个文件一起提交的事务。
- `lesson-revision` Skill 虽然写了草案、应用和旧版保留，Python/前端尚未落实对应状态机，**不能只改 Skill 就声称实现确认和撤销**。
- 本地右侧对话与课件修订通过 `backend/codex_driver.py` 调用项目配置的 `codex exec`，模型配置来自项目运行时。它不是这个桌面任务本身，也不是浏览器直接拿密钥访问模型。
- 带课件引用的问题当前会优先走答疑，绕过前端修改匹配；应支持“针对选中文本提出修改”，而不是只在聊天中建议却假称文件已改。
- 目前修改识别依赖关键词。例如“这页看不懂”可能被当重做，“不要修改课件”也可能命中。确认保护必须在后端执行，不能只靠前端正则或模型承诺。
- Codex 驱动的默认 sandbox 是 `danger-full-access`（环境可覆盖）。因此只给网页加确认按钮还不充分：提议/普通答疑阶段必须限制模型写权限，候选生成只在隔离工作区进行，最终课程写入交给已确认的后端操作。此处是源码默认值核查，不代表已核实用户机器每个运行进程的环境值。

## 3. 课堂界面

### 默认只读

中间栏顶端使用紧凑工具条：`只读 / 编辑`、`撤销上次修改`、`历史版本`。默认只读，阅读时不出现长排格式按钮，不挤占左侧大纲。

“只读”只禁止直接改课件文字；仍能选中文字提问、答题、翻页和查看笔记。

### 编辑模式

当前页提供标题输入和 Markdown 正文编辑区、即时预览；桌面并排，窄屏切换“编辑 / 预览”。支持插入文字和补充内容，不直接改 HTML DOM。

只增加用户要求的工具：H1、H2、H3、高亮、加粗、斜体、下划线。按钮对当前选文应用格式，没有选文时插入可编辑占位；不吞中文输入法组合过程。保存和取消固定可见。

- H1/H2/H3：分别插入 `#`、`##`、`###`。
- 加粗、斜体、高亮：分别使用 `**文字**`、`*文字*`、`==文字==`。
- 下划线：属于扩展而不是通用 Markdown 标准；可保存为严格无属性 `<u>文字</u>`，仅允许这一白名单，不开放任意 HTML。外部阅读器是否显示高亮/下划线取决于其扩展支持。
- 代码区单独编辑纯代码，不让粗体等格式插入程序字符；Markdown 代码围栏内部同样禁止工具栏自动套格式。
- 首期直接编辑标题、正文、教学代码；题干、选项、答案键不是普通笔记文字，不允许绕过题目校验直接改答案。修改题目走右侧“修订题目”草案并确认。

按“保存”才产生课件新版本；取消不修改当前课程。离开、翻页或切换项目前如有未保存内容，提示保存或放弃；草稿单独保存并明确标识，不能冒充已发布版本。

### 统一排版

沿用蓝白商务风和项目现有标准图标。统一内容字号：桌面正文 18px / 行高 1.75，H1 30px、H2 24px、H3 20px、标题字重 700；小屏正文 16px，标题依次 26/22/19px。标题层级在 Plan、正文预览、保存后课件和笔记阅读中一致；控件文案可更紧凑，但不把正文缩成小字。代码另用等宽字体，横向滚动不撑破布局。

## 4. 右侧 AI 修改：先确认，再生成，再应用

1. 用户输入修改要求（可带选区）。服务端区分“解释”与“修改”，不因出现“看不懂”就重做；否定修改、引用中的指令不能触发执行。
2. 返回修改提议：目标课件、受影响页面、修改什么、保留什么、是否增删题目。只形成待确认提议，不启动耗时课件重生成、不写当前版本。理解请求本身可以调用一次轻量模型。
3. 对话内显示 `确认生成修改稿 / 取消`。用户用文字“确认”时，只能对应当前项目唯一有效待确认提议；模糊、过期或多个提议需澄清。
4. 确认后，通过 Codex 和 lesson-revision 生成候选页。按目标限制可变字段，未涉及的页 ID、内容和题目保持稳定。校验失败保留旧版，展示具体失败阶段，不反复静默重做全章。
5. 展示新旧差异和 `应用修改 / 保留原版`。这是第二层保护：第一层授权花时间生成，第二层批准替换已完成内容。
6. 应用时检查项目、课件和原始版本仍一致；生成期间若用户编辑、撤销或切换项目，禁止覆盖新状态。成功后记录版本与对话事件，并显示 `撤销这次修改`。

追加练习也属于修改当前课件，必须进入相同确认/候选/应用链路。普通答疑、参考答案、模拟面试不需要修改确认，也不能暗中改文件。所有课件变更端点必须遵守这一保护，不能留旧 `/remediate` 作为无确认后门。

工具权限也要遵守阶段：提议/答疑只能读取授权内容；候选生成可在隔离的暂存区写文件，但不可覆盖活动课程或真实练习目录。研究工具需要写缓存时使用专属暂存区。不能用“提示词里写了不要修改”代替实际写权限限制。需要独立验证所用 Codex 环境能执行这样的权限约束；无法限制时不得启用无确认的写文件工具。

## 5. 撤销的语义

区分两种撤销：编辑器内 Ctrl/Cmd+Z 撤销未保存文字；“撤销上次修改”恢复上一次已应用版本。

- 每次手动保存、AI 应用和追加练习都生成不可变版本，保留发起原因、时间、前后版本和涉及页。
- 撤销不是删除历史文件，而是创建一次恢复事件，使当前版本指向相应旧内容；可以从版本历史重新恢复新版本。
- 保留作答和对话事件；按题目内容版本恢复通过状态。不能因恢复一个版本就清除后来所有学习记录，也不能把旧题正确答案套到新题。
- 撤销追加题目时，移除的是当前课件里的追加页及该版本的题目关联，已提交作答留在历史；用户自己写的练习文件绝不删除。其他来源引用同一题时不得连带删除。
- 不是任意历史聊天行都提供“倒带整个项目”。只有实际修改成功的消息显示撤销；较早版本通过历史面板恢复，并明确会替换哪些当前内容。
- 跨浏览器、重复点击、服务重启后仍根据后端记录工作；不能只在前端数组里保存“上一步”。

## 6. 存储与事务

推荐在当前项目拥有的课件目录内增量迁移，不再为本次编辑另造一套全局用户体系。旧课件第一次读取时作为基线导入，迁移失败保留旧文件。

```text
lessons/<lesson-key>/
  current.json                 # 当前版本指针
  versions/<revision-id>/
    manifest.json              # 页序、正文、代码、题目和关联
    answers.json               # 私有答案，不通过普通导出暴露
    lesson.md                  # 可阅读导出，按页保持稳定定位
  proposals/<proposal-id>.json # 提议、基线、确认/候选/应用状态
  events.jsonl                 # 手动保存、AI 应用、撤销、恢复
  drafts/<draft-id>.json       # 尚未保存的编辑草稿
```

以上为批准时的概念路径，并非最终文件布局；实际路径见本文开头。当前版本、答案和可读投影仍遵守单一指针原则，沿用现有学习项目隔离入口。

只有一份权威内容：版本 manifest。`lesson.md` 从同一版本确定性导出，无需再调用模型；不能让 Markdown 与 JSON 各自修改而悄悄不同步。Markdown 导出包含讲解、代码、可读题干和选项；点击、评分依然由应用提供。隐藏答案和未解锁敏感内容遵循现有展示权限。

如果用户在外部编辑导出的 Markdown，必须显式“导入为草稿 → 比对 → 应用”，不自动监听文件覆盖题目与状态。首期可只提供导出和应用内编辑，不承诺任意外部文档无损导入。

写入采用不可变版本目录＋最终原子切换指针；答案、Markdown 和 manifest 全写完、校验完才切换。题库使用可重试关联同步/提交记录，故障恢复后不能出现“页面已换、答案没换”。所有变更具备基线版本检查和幂等键；私有版本文件不能靠静态目录直接对外公开。

## 7. Skills 与 Python 分工

| 层 | 职责 |
| --- | --- |
| lesson-revision Skill | 理解教学问题，提出局部修改，说明修改理由和预期收益 |
| concept-teaching / quiz-designer / project-practice | 约束讲解、题目、练习和验收的教育质量 |
| Codex 运行时 | 在限定上下文中组织候选内容，不承担确认权限与最终写入保证 |
| Python | 验证确认、版本、项目、题目、保存事务、撤销、历史与导出 |
| 前端 | 只读/编辑、格式工具、草稿预览、差异、确认按钮、冲突和撤销反馈 |

编辑一个词、保存笔记、导出 Markdown、恢复版本不调用模型。只有理解不明确的修改要求和生成修改稿时需要模型。内容正确性审查不等于结构检查通过。

## 8. 必须完成的验收

### 权限与保存

- 直接说“这页看不懂”先澄清/答疑，不自动覆盖；明确“别修改”不得触发重做。
- 提出修改后不确认：文件、题库、版本不变，未发起课件生成。
- 确认生成但未应用：旧课件仍可用；取消候选不丢旧内容。
- 双击确认/重试不重复生成或应用；过期提议、跨项目、旧版本应用拒绝。
- 生成失败、保存失败、服务重启、题库同步失败分别测试，不只测成功路径。
- 从新部署用户目录和历史 JSON 课件迁移都可恢复。

### 编辑和显示

- H1/H2/H3、加粗、斜体、高亮、下划线逐项与组合测试；代码符号不能被格式化破坏。
- 未知 HTML、事件属性、script、恶意链接不可执行；下划线仅有限白名单。
- 编辑取消、保存、刷新、翻页、切项目、中文输入法与浏览器后退均不悄悄丢稿。
- 桌面、窄窗口、手机：无工具栏遮挡，无水平溢出；控件可键盘操作、焦点清晰；截图人工核对字号、对齐和按钮尺寸。
- 真实选区提问继续可用；选区修改进入提议而不是直接覆盖。

### 撤销和学习状态

- 手动保存→撤销→恢复；AI 修改→撤销；追加习题→答题→撤销；多次编辑后恢复旧版。
- 原题未变则通过记录仍在；题目变更不得继承旧正确状态；历史作答永不因撤销静默删除。
- 练习目录里的用户代码保持原样；题库跨来源关联不被误删。
- Markdown 导出的版本、正文、代码、页 ID 与当前课件一致，普通导出不泄露答案键。

### 教育质量

以零基础、精进、面试至少三个真实场景重新生成 Plan 与课件，独立评判章节依赖、节奏、实践和目标一致性。本科系统学习、临考复习、阅读现有项目、用户自带题目/技术栈另设场景，不能用前三个样本宣称全覆盖。所有不通过项保留原始输出与修订证据。

## 9. 实施顺序与当前边界

先完成版本存储与确认/撤销，再接入 Markdown 编辑，最后做真实课堂端到端和视觉验收；不能先画按钮再让旧端点继续绕过确认。

用户已认可本方案并授权在 main 实施。核心实现先后经过规范复查及独立质量复核；完整自动化结果为 Python 600 passed、Node 21 passed。浏览器撤销与框选等发布级验收仍按报告逐项补记，不能将“已批准”“已实现”“已验证”“已推送”混为一谈。原大纲评判保留在 `PLAN_EVALUATION.md`，不因本次修复而抹去历史失败。
