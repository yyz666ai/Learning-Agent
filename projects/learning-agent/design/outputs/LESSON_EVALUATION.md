## 本轮如何测试

使用本机项目配置的 DeepSeek + Codex 真实生成，不用模拟模型返回代替质量评审。评测数据隔离在 `evals/runs/2026-08-30-lesson-audit/isolated/`，不修改正式用户课程，不发布、不推送 GitHub。

本轮从合成的“已确认画像”开始，调用实际 Plan 生成、Plan 确认、课件生成处理函数；进阶诊断是明确标记的测试夹具，不是假装真人完成过诊断。意图识别全程、完整岗位/技术栈入库、后续全部章节、长期掌握、同事机器部署不是本轮已经验证的内容。

每个模型调用评测上限设为 **360 秒**；生产默认 600 秒。评测超时说明本轮未在预算内完成，不能直接推论生产 600 秒也必定失败。三个独立样本并行运行，时间仅供定位，不是稳定性能统计。

代码验证：`pytest -q` 本轮 **440 passed，1 warning，64.63 秒**；前端交互测试 **6 passed**。这些结果不覆盖真实模型生成的语义正确性。

## 已实际通过的部分

### Python 零基础首章

- 课件包含软件安装入口、不同系统验证命令、交互式与脚本方式、短代码和中文注释。
- 11 页中有 3 道选择题、1 份课后编程作业、4 道含答案/遗漏点/追问的面试简答。
- 后端实际创建 `projects/python/hello/README.md` 和空白 `main.py`，没有把完整答案自动写进学生文件。
- 两段示例 `repl-print`、`first-script` 实际执行退出码均为 0，输出均为 `你好，Python`。只运行了已检查的这两段安全 Python 示例，不代表所有命令和平台安装步骤都执行过。
- 浏览器打开真实课件，Markdown 和代码框可见。截图：`evals/runs/2026-08-30-lesson-audit/interview-page.png`。
- 实际先选错 `version python3`，再选对 `python3 --version`，服务端该题 `attempt_count=2`、`wrong_count=1`；答对后解锁并自动翻页。
- 题库实际为 8 项，不再仅靠“注册函数存在”判断成功。
- 三道点击题实际作答后，课件末尾可以看到编程作业和 4 道面试题；点击第一道题可展开参考答案、回答结构、遗漏点与追问。
- 右侧请求“结束模拟面试，只告诉我作业第一步，不要完整答案”，实际回答先打开空白 `main.py`，没有倾倒答案。该答疑同步进入课件笔记；是否能持续辅导到独立完成仍未验证。

### 右侧模拟面试短对话

首次真实回复：

> 好，现在我是 Python 岗位面试官，面试范围就是本章「环境就绪与第一次运行」。第一道简答题：请介绍一下：Python 是什么？解释器是做什么的？

浏览器提交错误回答“解释器就是写代码的编辑器”后，实际回复先肯定“Python 是语言”，再纠正编辑器与解释器的区别，并追问执行代码时发生什么。

评价：单轮相关性和纠错通过；一次样本不足以证明稳定多轮模拟。它仍使用“口述、我听完”的措辞，当前没有录音功能；更合适的说法是“把回答打在右侧，我再评价”。问答实际写进 `memory/conversation-events.jsonl` 和课件笔记，但不是独立、可恢复的模拟面试状态机。

## 不通过项与根因

### F01：研究阶段没有有效结果也继续消耗时间

零基础 Go 日志中，`tools/web_search.py` 返回：

> I'll research the official Go documentation on these topics for you. Let me search for the official resources.

随后模型逐个请求 16 个官方页面的 HTTP 状态，每个 URL 上限 15 秒。该阶段是本次延迟的一个直接来源；一次返回不能证明搜索服务永远失效。

根因线索：脚本取第一个 `output_text` 就作为结果，没有检验是否完成检索、是否包含来源/正文；HTTP 200 也不是读过资料或内容可靠的证明。完整路线强制新研究，使该路径成为生成 Plan 的前置阻塞。

建议：将“检索成功”的契约设为可核验的来源＋事实；优先版本化官方知识缓存，明确刷新条件；研究阶段独立限时、记录子阶段并可恢复。不能通过移除来源审核来伪造成功。

### F02：熟练者又被安排重新摸底

真实 Go Plan 已引用“诊断 4 题、80%、强项 HTTP 与单测”，但第一阶段仍是“3–4 道迁移题确认强项、钉住缺口”。首版 PPT 继续复习 handler 和表驱动测试。

评价：有针对性但重复诊断、第一步不够直接。期望：第一章直接给一个取消失效的最小复现，先观察并定位；只在暴露具体缺口时补讲，不再完整重做已确认诊断。

修改涉及 `learning-plan`、`adaptive-lesson-flow`、`project-practice` 以及 Python 的安全兜底 Plan。只改其中一处可能被其他提示覆盖。

### F03：课件返回了，但结构门禁要求再次生成

Go 首版课件共 13 页，第一段代码超过当前渐进阈值。重新运行解析器，原始输出与规范化输出均报：

```text
ValueError: long generated code requires a progressive build-up page
```

这不是网络断开，也不是“没有教案”。模型输出违反当前教学契约，自动修复需要另一次模型调用，拉长等待。应保留首次失败并验证修复；不能只记录最终成功。

**修复后仍失败的具体根因已经复现**：第二版增加短骨架，基础解析通过，但 `lesson_generator.py` 的覆盖校验要求每个知识点的完整标题（只去除空白）必须逐字出现在所引用页面正文中。此处标题是长句 `快进确认已掌握区（HTTP handler 实现、表驱动单元测试）`。修复页实际讲了 handler、注册、表驱动测试，并在 `scope_evidence` 中关联了正确 ID `http-handler` 和 5 个页面，却没有照抄这整句话，最终报：

```text
ValueError: repaired lesson drifted away from a covered knowledge point
```

人工对照内容，这是一例“完整字符串出现”替代“教学覆盖判断”导致的过严拒绝。修复提示确实要求原样出现标题，所以也存在模型未遵守输出契约的问题；不能把它误报为纯网络故障。首版与修复版合计约 **503 秒**，重试成本很高。

建议把覆盖检查拆成：知识点 ID/页面引用的确定性检查＋各概念的语义覆盖检查；后者需要正例/反例评测，既不能要求照抄标题，也不能仅凭模型自报 ID 就放行。保留原课件，明确返回失败的具体检查项。

建议：区分“已经掌握的基础骨架”与“首次出现的陌生 API”；将分层规则纳入结构化生成范围，并尽量定点补页，避免每次全章重写。是否允许熟练者跳过骨架必须设计确认，不能直接放宽所有校验。

### F04：追加练习的用户要求在前端丢失

`frontend/js/app.js` 的 `generateSupplementalPractice(instruction)` 只把 instruction 写进聊天气泡；请求固定 `count: 3`，module 优先取当前任务，没有发送完整 instruction。后端 `SupplementalPracticeRequest` 不包含这份完整要求，并要求所有追加题都为 2–4 选项的选择题。

因此“追加 5 道更难的循环题”和“再给一个编程项目”不能可靠按原意生成。建议传递完整要求，并让模型输出明确题型/数量/难度，后端验证和保存；不能靠正则替用户做默认选择。

### F05：编程作业与课堂完成不是同一个概念

当前契约每章只有一份 homework，且选择题答对即可进入下一章，代码作业自主完成。`evaluate_completion` 在该情况下返回固定 `mastery_score=70`；前端又将完成知识点比例显示为“掌握”。

评价：允许自主练习合理，但不能把“翻完课堂”包装成“独立编程能力已达标”。需要分别显示课堂完成、练习完成、独立迁移、复习证据。要支持更多编程练习，需调整题型与作业模型，不只是把题量数字加大。

### F06：作业答案与面试规则尚不统一

`exercise-coach` 要求逐级提示，明确不能因为“直接给答案”跳过门禁；用户本次需求包含获取答案。产品上建议默认提示、显式“查看参考答案”允许查看，但标注 assisted，并提供新变式独立完成，不能偷偷记掌握。

`build_prompt` 和 `exercise-coach` 也有“回答后不要追加简答题”的通用规则，和模拟面试冲突。此次模型仍成功追问，证明不能宣称“完全不能面试”；但规则应按普通答疑与模拟面试分流，而不是依赖模型临场选择忽略哪条。

### F07：未实现选中课件内容 → 提问 → 引用框

现有聊天请求只有 message、history、lesson_id，没有 page_id、课件版本和引用内容；lesson_id 在聊天处理函数中主要用于记录笔记，没有显式传入 `build_prompt`。前端没有 PPT 文本选区转引用框的流程。

不能只改 Skill：前端必须捕获选区，后端必须验证引用范围，模型提示必须把引用当作资料而非指令。

### F08：内容与界面还有误导点

- 同页出现两份“本页请做”：生成 Markdown 自带一次，前端又加一份通用提示，可能一份要求动手、一份只让翻页。
- 终端代码框把 `python3` 和带 `>>>` 的 Python 交互提示混在一起，复制整段不等于可直接执行，应区分终端命令、提示符与输入代码。
- 面试 Plan 承诺“回听口答记录”，产品没有录音功能，不能写这样的学习步骤。
- Python 首章要求学生在相对路径进入课程目录，但从哪个目录开始不清晰；应优先指向实际的“打开练习文件夹”入口。
- 单章全部步骤覆盖不代表知识正确性完全验收；官方版本敏感命令及概念精度仍需独立内容复核。

### 补充阻断项 F09：刷新后前端丢失已答状态与课堂对话

真实操作：完成三道点击题 → 进入第 11 页 → 右侧模拟问答与作业提示 → 刷新 → 再点已有 Python 项目。

实际结果：回到第 1 页，第 4–11 页再次禁用；右侧只显示欢迎语和“第一课已经打开”，刚才两轮课堂问答未恢复。后端题库和 `conversation-events.jsonl` 仍有记录，不是文件被删除。

确定性根因之一：`frontend/js/artifact.js` 的 `applyManifest` 每次执行 `state.quizAttempts = []`，没有恢复服务端已答对记录。聊天区还需接通课堂历史回放，而不是只有 onboarding 历史恢复。证据保存在 `refresh-dom.txt`。新旧课件必须按版本区分作答，不能简单把旧答案全部套到新版本。

## 框选提问设计（待确认，尚未实现）

推荐首期只做文字/代码选择，不做矩形截图。后者需要图片传输及视觉模型，成本和边界不同。

1. 只在 PPT 教学区域选择非空文字或代码；出现“提问”按钮。
2. 点击后右侧输入框上方出现一张摘录框：课件标题、页码、短摘录、取消按钮。保留完整选区快照，输入框获得焦点，不自动发送。
3. 用户输入问题，再把 `lesson_id + page_id + revision + quote + question` 一起发给服务端。建议首期一条引用、选区最多 2000 字，长内容提示缩短。
4. 服务端验证当前用户/项目/课件/版本与引用内容。引用是资料，不允许其中的文字覆盖 Skill 或系统规则。
5. 切换项目清除引用；课件重做后标记过期并要求重新选择；普通翻页保留已选页码。失败保留引用和输入，取消只移除引用。
6. 提问成功写入对话与课件笔记，回答引用对应页，不误挂到后来翻到的页面。

普通答疑继续“解答后不强制反问”；显式模拟面试改为“一问 → 等回答 → 评价 → 追问或下一题”，保存题目、回答、提示级别与会话进度。

## 未完成的验收与后续顺序

1. 先解决真实生成延迟和修复链路，再重跑同样样本并保留首次失败。
2. 按确定的设计补全选中引用、练习要求传递、答案策略、模拟面试状态。
3. 复测完整岗位/技术栈、用户提供真题、多个后续章节、代码批改、刷新恢复、手机和故障重试。
4. 最后由真实零基础学习者按课件完成独立编程任务；自动化测试不能代替这一项。

本轮只新增评测文档与隔离证据，没有把新增交互或上述修复声明为已完成。

### 已实现的改动

1. **生成边界**：修复教学标题包装、合法改写与字段串位造成的误拒；保留结构、正确答案、代码铺垫和范围证据检查。研究工具不再把“我将搜索”当研究结果，增加时间预算。
2. **引用提问**：新增课件文字/代码选区、提问按钮和可取消引用草稿；不自动发送，不清空已有问题。服务端验证用户当前课件、版本、页码及选文内容；失效引用返回可理解的提示。
3. **恢复**：课堂历史从用户目录回放；答题通过按题干、选项、答案以及题页代码/Markdown 版本恢复。旧版本答案不解锁新题。旧记录若缺少足够版本证据，保留历史但不冒充当前通过。
4. **追加练习**：原始要求完整传给模型，不固定三题，也不强制全是选择题。支持 programming/project，带里程碑、提示、标准，追加至 PPT 并注册到题库；真实练习目录生成 README。保存失败回滚新增课件和本次写入文档。
5. **模拟面试**：显式进入/退出文字面试模式，模式随成功对话保存；一次一问，点评后追问，显式索要参考答案可以展示。失败的半截回复不保存为完成答案。
6. **规则一致性**：concept-teaching 不再同时要求旧 HTML deck、终端输出门禁和新版 JSON Manifest；project-practice 增加 Go 取消与资源测试参考；quiz-designer 区分点击题和编程题。Skills 改变教学约束，Python 仍负责结构、状态、隔离和保存。
7. **提示显示**：追加练习的提示采用默认关闭的安全折叠块，不再把 details 标签原样显示；未知 HTML 仍转义。

### 真实交互结果

- 第一次追加进阶项目 69.14 秒，实际加入 1 个 project；修订规则后再次生成 71.97 秒。新版已采用等待全部子任务、atomic、started/done 和正常/取消/资源回收三条验收路径，不是问候程序。
- 新版项目仍有一处需明确的测试措辞：先“断言资源未退出”是在确认反例，不能同时称为修复前应失败、修复后变绿的同一测试。正确红绿测试应始终断言**预期正确行为**（取消后资源退出），修复前失败、修复后成功。已经列为内容审查项并补进 project-practice 参考，尚未对这条最后新增约束再次生成样本，不能把出题成功等同于测试代码已验证。
- 第一轮面试首问 8.92 秒、错误回答点评 7.26 秒、参考答案 15.35 秒、引用解释 15.46 秒；第二轮分别 6.52／14.96／14.69／9.46 秒。两轮实际服务均完成并恢复历史。
- 浏览器在独立 8790 测试页作答第一道题，自动进入下一页；刷新并重新进入项目后，第 4–6 页仍解锁，第 7 页以后仍被下一道未答题阻挡。历史对话恢复。不是只看后端 JSON 推测前端恢复。
- **浏览器实际拖选尚未验收成功**：接口、选文状态和模拟 DOM 行为测试通过，但浏览器自动化拖选未产生实际选区。不能据此宣称真实“拖选 → 引用框 → 发送”已经端到端通过。原测试页出现非测试文字时已暂停并保留，未代用户发送或清空；另开测试页完成恢复验证。

### 独立审查与确定性回归

两轮独立代码审查发现并修复：选文丢失代码符号、答题指纹遗漏代码材料、正文内代码被当排版清洗、提示折叠标签与前端渲染不兼容。最后复核这些修复未再发现阻断项。

最终范围校验重放：首轮 beginner/advanced call-2、面试 call-4/call-5 均保留原始模型文本，通过最新结构与范围检查。重要根因是校验器曾把知识点 ID `go`、`goroutine` 当元数据从正文删除，连真正的语言术语也删除了；另有标题编排措辞与多余引用页误拒。现在保留真实术语，只去除明确 ID 标签，并要求至少两页实际支持、全部实质概念仍有覆盖；伪造引用、未知页面仍拒绝。

### 最后一轮修订及真实代码执行

`103124-lesson-retest` 的第 8 页修复版，未经手工修改直接提取到隔离目录执行。新增测试文件只用于验证，不冒称模型生成了这些测试。

- 正常完成：100ms 内不能提前返回，约 5 秒后完成，任务计数归零。
- 主动取消与复用：确认任务已开始后取消，1 秒内退出；连续 3 次均归还计数。
- 并发取消：12 个任务全部启动后统一取消，全部退出、计数归零。
- `go test -race -count=3 -v ./...`：三项测试各执行三轮，通过，未检测到数据竞争，总计约 16.57 秒。这覆盖该示例，不代表所有 Go 作业或真实断网环境通过。

独立评测结论仍是**整份进阶教案部分通过**：修复版与红绿测试要求已经改正确，但错误版 handler 立即返回后会取消 Context，worker 可能在进入 Sleep 前就退出。因此作业第 1 步“响应秒回，5 秒后一定打印”不可靠。建议错误版也等待任务，仅保留 Sleep 不可中断；已补进 project-practice 的 Go 参考。此问题不能通过放宽结构校验解决。

最终确定性回归：Python 562 项、Node 13 项；Python 有一条测试客户端依赖弃用提示，与本轮功能失败无关。规则文案测试只能防止已知约束被删，不能替代真实生成或教学质量评价。

部署边界：本轮修改保存在本地 main 工作区，未提交或推送 GitHub，未重启 8787 服务，也未覆盖其已发布教学快照。隔离测试通过不意味着原浏览器里已经运行新后端；正式应用前还需处理浏览器拖选验收及上述内容问题。
