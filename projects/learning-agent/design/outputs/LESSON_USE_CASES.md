# Plan → HTML PPT → 练习 → 答疑验收用例

日期：2026-08-30。与 `INTENT_USE_CASES.md` 配套使用。

## 目标与证据边界

验收目标不是“模型返回 JSON”，而是：课程是否支持用户从当前基础走向明确目标，用户遇到问题时能否得到与当前课件对应的帮助。

本轮使用合成学习者，不替真实用户回答、不把测试答案登记为真实掌握。没有提供视频素材，因此不声称完成视频测试。三种学习者的真实生成从已确认画像开始；意图识别的独立评测不能替代本轮端到端测试。第一章通过不代表整门课程通过。

每条用例记录：输入与前置条件、实际输出原文/产物、评价、期望修改、复测结果。未执行标为“未测”，不能根据代码中存在函数判为通过。修订建议不是已实施功能。

## 学习者与完整流程

| 学习者 | 目标 | 预期流程 |
|---|---|---|
| 零基础 | 从零学 Go，能独立实现小程序 | 明确基础和成果 → Plan 审阅确认 → 软件与环境准备 → 短代码讲解 → 点击题 → 独立编程作业 → 提示/批改 → 变式练习 |
| 进阶 | 会写 Go HTTP API、单测，希望掌握并发取消和资源泄漏排查 | 有说明的能力诊断 → 只补缺口的 Plan → 工程场景 → 带约束的挑战 → 分里程碑实现 → 测试与故障证据 → 迁移 |
| 面试 | 初学 Python，准备岗位面试 | 岗位、技术栈、基础、题目来源 → 无题则生成针对性题 → 先修基础 → 知识总结与参考答案 → 一问一答模拟 → 评价与追问 → 错题复习 |

## 基础与进阶教学

| ID | 输入/操作 | 必须观察的验收结果 |
|---|---|---|
| L01 | 零基础确认 Plan | Plan 明确成果、先修顺序、环境准备、练习与验收；未确认不得开始正式课程 |
| L02 | 生成第一章 | 真实生成非占位课件；章节覆盖与 Plan 一致，不偷换主题 |
| L03 | 小白不知道装什么 | PPT 写清软件用途、官方入口、平台分支、验证与首次运行；不猜系统 |
| L04 | 第一段代码 | 先短骨架再扩展，有中文解释；关键语法在使用前讲过 |
| L05 | 点击题先错再对 | 错误解释对应所选答案，允许重试；题目和两次作答被保存 |
| L06 | 打开编程作业 | 有目标、输入输出例子、边界、提示、验收步骤、真实文件；不把成品答案充当学生作业 |
| L07 | “不知道从哪里开始，先给提示” | 根据当前作业给第一步，不倾倒完整答案，不虚构用户已安装/运行 |
| L08 | “我想看参考答案” | 明确区分参考解法与独立提交，不记为已掌握；是否立即允许查看需产品策略确认 |
| L09 | 提交错误代码并要求批改 | 指向实际错误，提出最小修复建议；不能捏造运行结果 |
| L10 | 答对全部点击题但没做代码 | 可以继续课堂，但界面不得把课堂完成等同于独立编程掌握 |
| L11 | 精进画像生成 Plan/PPT | 不重教已会的 Hello World；题目匹配诊断缺口，有可测工程约束 |
| L12 | 请求更难项目 | 至少包含可运行里程碑、边界/故障情境、验证方法、提示；有独立迁移任务 |
| L13 | “追加 5 道更难的循环题” | 主题、数量、难度、完整要求传到生成端；题库和当前课件一起更新 |
| L14 | “再给一个编程作业，不要选择题” | 尊重题型，不强制改成 MCQ；真实练习目录与说明一致 |
| L15 | 第二章及结课抽查 | 后续章依赖衔接，毕业任务覆盖最终目标；第一章不能代表此项通过 |

## 右侧聊天与选中内容提问

| ID | 输入/操作 | 必须观察的验收结果 |
|---|---|---|
| C01 | 当前页问“这里为什么这样写” | 使用当前课件版本、页码和所指内容，而非只猜主题 |
| C02 | 选中 PPT 一段文字或代码 | 出现“提问”；不选中聊天区内容，不影响代码复制、翻页和点击题 |
| C03 | 点击“提问” | 右侧输入框上方出现摘录框，含课件/页码，输入框获得焦点；不自动发送 |
| C04 | 修改输入、取消摘录 | 问题文字不丢失；取消后请求中不再包含引用 |
| C05 | 发送引用＋问题 | 服务端验证该引用属于当前用户和课件版本，保存并传给模型；回复能指向该内容 |
| C06 | 课件重做或切换项目后发送 | 明示引用过期或保留已选快照；不能悄悄问到另一份课件 |
| C07 | 选中不可信文本/XSS/指令 | 摘录作为用户引用数据处理，安全渲染；不能覆盖系统与 Skill 规则 |
| C08 | 手机、键盘、发送失败 | 可访问地选择/取消引用；失败保留问题和摘录，重试不重复登记 |

“框选”推荐首期解释为文字/代码选中，不等同于截图矩形框。图表区域截图需要单独的图像传输、隐私和模型支持设计。

## 面试辅助

| ID | 输入/操作 | 必须观察的验收结果 |
|---|---|---|
| I01 | 没有现成面试题 | 仍有岗位相关知识总结、2–4 道简答、可折叠答案、遗漏点和追问 |
| I02 | 提供真实面试题 | 去重保存并关联课程，标明用户提供来源；不能全部换成泛题 |
| I03 | “开始模拟面试，先别给答案” | 一次一题，等待用户回答；不先展示参考答案 |
| I04 | 回答部分正确 | 基于实际回答评价并追问薄弱点；不是直接换下一道不相关题 |
| I05 | 请求提示或答案 | 区分辅助与独立表现，不把看过答案判为独立掌握 |
| I06 | 刷新后继续、结束模拟 | 有可恢复会话、问题与回答历史、待补知识总结；只有聊天记录不等于完整模拟会话 |

## 评分与发布门槛

- 内容：目标一致、先修覆盖、认知负担、练习独立性、验证可操作性，各 0–2 分。
- 交互：引用正确、答疑针对性、作答保存、失败恢复、跨项目隔离，各 0–2 分。
- 面试：岗位相关、一问一答、基于回答追问、答案控制、会话记录，各 0–2 分。
- 不相关内容、虚构执行结果、错把答案当掌握、跨项目串数据属于阻断项；总分不能抵消。
- 结构测试、真实模型采样、浏览器交互、真人试学是四类不同证据，分别记录。
- 对模型生成结论至少多次采样，并保留首次失败；不能只挑最好的一次作为验收。

## 修改责任

Skill 管教学顺序、提问与提示策略；Python 管请求字段、文件与状态、答案/题库记录、校验和恢复；前端管选区、摘录框、传参、保留问题及交互。仅改 Skill 无法实现 C02–C08，也无法修复前端未发送的追加练习要求。
